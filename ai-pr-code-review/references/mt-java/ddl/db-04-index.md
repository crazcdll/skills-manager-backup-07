## DB-04 MySQL 索引规范（审查精要）

| 编号 | 规则 | 级别 |
|------|------|------|
| MT:N001 | 避免索引创建误解（不是每个查询都建索引，也不吝啬索引） | P3 |
| MT:N002 | SQL性能目标：至少range级别，要求ref级别，const最好 | P3 |
| MT:N003 | 组合索引区分度最高的在最左边；等号条件列前置于非等号 | P3 |
| MT:N004 | VARCHAR字段索引必须指定索引长度（通常20长度达90%区分度） | P3 |
| MT:N005 | JOIN字段必须有索引且类型一致；OLTP场景超过3表JOIN需重点评估 | P3 |
| MT:N006 | ORDER BY字段应是组合索引的一部分且放最后，避免filesort | P3 |
| MT:N007 | 利用覆盖索引避免回表 | P3 |
| MT:N008 | 大分页（offset>10000）必须用延迟关联或游标分页 | P3 |
| MT:N009 | 防止隐式转换导致索引失效（WHERE条件字段类型必须与表一致） | P3 |
| MT:N010 | 唯一索引命名 uniq_字段名，普通索引命名 idx_字段名 | P3 |

### 强制禁止
- ✗ 禁止超过3个表JOIN
- ✗ 禁止大分页查询使用 LIMIT 100000, 20
- ✗ 禁止 WHERE 条件字段类型与表字段类型不一致
- ✗ 禁止在索引列上做函数/计算/类型转换

### 检查点
- [ ] 执行计划是否达到 range 级别以上
- [ ] 组合索引顺序是否合理（区分度高的在左）
- [ ] VARCHAR 索引是否指定了长度
- [ ] JOIN 字段是否都有索引且类型一致
- [ ] 大分页是否优化
- [ ] 索引命名是否规范（uniq_/idx_ 前缀）
- [ ] WHERE 条件是否存在隐式类型转换
