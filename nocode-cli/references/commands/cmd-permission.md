# permission 命令详细规则 — 作品权限管理

## 概述

管理作品页面可被访问的范围，包含三部分能力：

1. **链接分享权限切换**：外部公开 / 内部公开 / 指定对象
2. **指定对象白名单维护**：添加、删除人员和部门
3. **隐藏作品 NoCode 角标**

## 权限类型说明

| 权限类型 | 取值 | 说明 |
|---------|------|------|
| 外部公开 | `EVERYONE` | 所有人可访问，**包括非美团人员** |
| 内部公开 | `MEITUAN` | 仅美团内部员工可访问 |
| 指定对象 | `SPECIFIED` | 仅白名单内的指定个人或部门可访问 |

## ⛔ 强制约束

1. **切换到「外部公开」必须经用户二次确认**：外部公开意味着非美团人员也能访问，存在信息安全风险。切换前必须向用户明确说明风险并获得确认
2. **切换到「内部公开」需提醒用户**：所有内部员工均可访问，切换前需提示用户注意信息安全
3. **删除人员/部门权限必须经用户明确确认**：执行前需展示将要移除的人员姓名/MIS 号或部门路径，获得确认后执行
4. **禁止删除作品作者的权限**：作品作者（`isOwner=true`，列表首位）的权限不可移除
5. **添加人员前必须校验 MIS 号有效性**：通过用户搜索接口确认 MIS 号存在，避免添加无效账号
6. **⛔ 部门相关操作必须使用「完整部门路径」**：`search-org` 和 `add --org` 都**不支持模糊关键词/部门简称**，必须传从顶层开始逐级用 `/` 连接的完整路径。传简称会返回空结果（不报错），极易被误判为「部门不存在」。向用户索要路径时，**优先引导从大象用户信息卡片的「部门」一栏复制**。详见下方 [search-org](#permission-search-org-搜索部门) 小节
7. **权限变更后需部署才能生效**：已部署的作品会自动更新为最新权限配置；未部署的作品需手动部署后生效。操作完成后必须告知用户这一点
8. **权限切换可能被团队策略或审批流拦截**：遇到「团队已设置强制指定对象」「有审批中的权限变更申请」等错误时，禁止重试绕过，需如实告知用户

## 命令列表

### permission get — 查看当前权限配置

```bash
nocode permission get <chatId>
nocode permission get <chatId> --json    # JSON 格式输出
```

返回当前链接分享权限类型；当为「指定对象」时，同时返回已授权的人员列表和部门列表。

**返回字段：**

| 字段 | 说明 |
|------|------|
| `authType` | 当前权限类型：`EVERYONE` / `MEITUAN` / `SPECIFIED` |
| `persons` | 已授权人员列表（`displayName` 形如 `姓名/mis号`、`avatarUrl`、`isOwner`） |
| `orgs` | 已授权部门列表（完整部门路径字符串数组） |
| `hideBadge` | 是否隐藏 NoCode 角标（`true` 隐藏 / `false` 显示） |

### permission set — 切换链接分享权限

**⛔ 切换到 `EVERYONE`（外部公开）前必须获得用户明确确认；切换到 `MEITUAN`（内部公开）前必须提醒用户信息安全风险。**

```bash
nocode permission set <chatId> EVERYONE     # 外部公开（所有人）
nocode permission set <chatId> MEITUAN      # 内部公开（美团内部员工）
nocode permission set <chatId> SPECIFIED    # 指定对象（指定个人或部门）
```

**规则：**

- 切换到 `SPECIFIED` 后，需继续通过 `permission add` 添加人员/部门，否则仅作品作者可访问
- 切换成功后需提醒用户：已部署的作品自动更新权限配置；未部署的作品需手动部署后生效
- 团队开启「作品权限强制指定对象」策略且当前用户非团队管理员时，切换会被拒绝
- 存在「审批中」的权限变更申请时，切换会被拒绝，需等审批完成

### permission add — 添加人员/部门到白名单

**⛔ 仅在权限类型为 `SPECIFIED`（指定对象）时有意义。** 若当前权限非 `SPECIFIED`，应先提示用户切换。

**⛔ 必须先询问用户：** 执行前必须明确询问，禁止自行猜测或编造 MIS 号、部门路径：

1. **添加人员还是部门？**
2. **人员的 MIS 号是什么？**（支持多个，逗号分隔）
3. **部门的完整路径是什么？**（必须是完整路径，不能是简称）
   - 引导用户**从大象用户信息卡片的「部门」一栏整段复制**，这是最便捷的获取方式
   - 详见 [引导用户获取完整部门路径](#引导用户获取完整部门路径推荐话术) 小节的推荐话术

```bash
# 添加人员（单个或多个，逗号分隔）
nocode permission add <chatId> --user <mis1>,<mis2>

# 添加部门（必须是完整部门路径）
nocode permission add <chatId> --org "公司/美团/核心本地商业/基础研发平台/Agent平台部"
```

**规则：**

- 添加人员时先通过用户搜索校验 MIS 号有效性，无效的 MIS 号会被拒绝并提示
- **`--org` 必须传完整部门路径**，推荐直接复制 `permission search-org` 返回的 `name` 字段值（含 `公司/` 前缀）
- CLI 会先调用部门校验接口确认路径有效，无效会直接报错不写入
- CLI 会自动补全 `公司/` 前缀，并在写入后**回读校验**确认真的保存成功
- 单次批量添加人员上限 100 个
- 重复添加已存在的人员/部门会被忽略，不报错

**⚠️ 部门链必须带 `公司/` 前缀（已实测验证）：** 若传 `美团/...`（缺 `公司/`），后端会**返回成功但实际不写入**（静默失败，`orgs` 仍为空）。CLI 已自动补前缀 + 回读校验规避此问题；若直接调接口需自行注意。

### permission remove — 从白名单移除人员/部门

**⛔ 移除前必须经用户明确确认，并展示将要移除的对象。**

```bash
nocode permission remove <chatId> --user <mis> --confirm
nocode permission remove <chatId> --org "公司/美团/核心本地商业/基础研发平台/Agent平台部" --confirm
```

移除部门时 `--org` 同样必须传**完整部门路径**，建议先用 `permission get` 查看 `orgs` 列表并直接复制其中的路径值。

**规则：**

- `--confirm` 为必需参数
- 禁止移除作品作者（`isOwner=true`）的权限
- 移除后该人员/部门立即失去访问权限

### permission search-user — 搜索用户

用于确认 MIS 号是否有效、或根据姓名查询 MIS 号。

```bash
nocode permission search-user <keyword>
```

返回匹配的用户列表（`misId`、`misName`、`headUrl`）。支持按姓名或 MIS 号搜索。

### permission search-org — 搜索部门

```bash
nocode permission search-org "<完整部门路径>"
```

#### ⛔ 必须传「完整部门路径」，不支持模糊关键词

该接口**按完整路径精确匹配**，不是模糊搜索。传部门简称或中间某一级名称，会返回**空数组 `[]`**（HTTP 200，不报错），非常容易被误判为「该部门不存在」。

```bash
# ✅ 正确：从顶层开始的完整路径，逐级用 / 连接
nocode permission search-org "美团/核心本地商业/基础研发平台/Agent平台部/研发质量与效率部/Agent 基建组/Agent 研发环境组"
# → [{ "name": "公司/美团/核心本地商业/.../Agent 研发环境组", "depth": 0 }]

# ❌ 错误：以下写法均返回空数组 []
nocode permission search-org "Agent 研发环境组"     # 只有末级名称
nocode permission search-org "Agent平台部"          # 只有中间某一级
nocode permission search-org "基础研发平台"         # 只有中间某一级
```

**因此：无法凭简称反查完整路径。** 若用户只给了部门简称，**必须直接向用户索要完整部门路径**，禁止自行拼接、猜测或用简称反复尝试。

#### 💡 引导用户获取完整部门路径（推荐话术）

**首选方式：从大象（企业 IM）用户信息卡片复制。** 这是最快、最不易出错的途径：

> 在大象里点开你自己（或该部门任一同事）的头像，打开用户信息卡片，上面的「部门」一栏就是完整部门路径，直接整段复制发我即可。

其他可选途径：NoCode 权限面板已授权部门列表、OA 组织架构页面。

**⚠️ 向用户要路径时的注意事项：**

- 大象卡片复制出来的路径**通常以 `美团/` 开头，不含 `公司/` 前缀**，这是正常的 —— CLI 会自动补全，不要因此要求用户重新提供
- 路径中可能含空格（如 `Agent 基建组`），属正常，**不要擅自删除或改写**
- 不要要求用户「确认一下是不是完整路径」这类无效追问，直接拿到手就走 `search-org` 校验，校验失败再回头问

#### 返回字段

| 字段 | 说明 |
|------|------|
| `name` | 部门完整路径，**注意会带 `公司/` 前缀**，如 `公司/美团/核心本地商业/...` |
| `depth` | 相对搜索根节点的层级深度（精确匹配单个部门时为 `0`） |
| `orgId` | 部门 ID（可能不返回） |

**⚠️ 添加部门权限时 `--org` 传的是 `name`（完整部门路径），不是 `orgId`。** 推荐直接复制返回的 `name` 原值（含 `公司/` 前缀）传给 `permission add --org`，已验证可正常写入。

#### 为何不用 orgId？

后端 `api/auth/append-permission` 保存部门时，`roleCode` 传的就是**部门链（完整路径字符串）**，而非 `orgId`（作品权限面板 `AuthPanel.jsx` 即如此：`{ roleCode: 部门路径, roleType: 2 }`）。因此**不需要先把路径转成 orgId 再添加**，只需校验部门链有效性。`orgId` 仅用于辅助确认唯一性。

> 注：团队（`team`）/项目（`project`）权限面板确实会先转 `orgId` 再传，但**作品（`artwork`）权限不是**，不要搞混。

搜索结果有多个候选时，必须向用户展示候选列表并让用户确认，禁止自行选择。

### permission badge — 隐藏/显示 NoCode 角标

```bash
nocode permission badge <chatId> --hide     # 隐藏角标
nocode permission badge <chatId> --show     # 显示角标（默认）
```

**说明：**

- **隐藏**：作品不展示角标，需通过对话链接才能查看对话
- **显示**：作品右下角展示 NoCode 角标，点击可查看对话

不带 `--hide` / `--show` 时，返回当前角标配置状态。

## 典型流程

### 场景 1：把作品设为仅指定人员可访问

```bash
# 1. 查看当前权限配置
nocode permission get <chatId>

# 2. 切换为「指定对象」
nocode permission set <chatId> SPECIFIED

# 3. 校验 MIS 号有效性（先询问用户要添加谁）
nocode permission search-user zhangsan

# 4. 添加人员
nocode permission add <chatId> --user zhangsan,lisi

# 5. 确认结果
nocode permission get <chatId>

# 6. 告知用户：需部署后权限才生效（已部署的作品会自动更新）
```

### 场景 2：给某个部门开放访问权限

```bash
# 1. 确认当前是「指定对象」
nocode permission get <chatId>

# 2. ⛔ 向用户索要【完整部门路径】
#    禁止用简称搜索（会返回空结果），也禁止自行拼接路径
#    推荐话术（告诉用户去哪儿拿，而不是只说"要完整路径"）：
#    「在大象里点开你自己（或该部门任一同事）的头像，打开用户信息卡片，
#      上面的「部门」一栏就是完整部门路径，直接整段复制发我即可。」

# 3. 用完整路径校验部门是否存在
nocode permission search-org "美团/核心本地商业/基础研发平台/Agent平台部"
# → 返回空数组 说明路径不对，要回头找用户确认，不要换关键词重试

# 4. 直接复制上一步返回的 name（含 公司/ 前缀）添加
nocode permission add <chatId> --org "公司/美团/核心本地商业/基础研发平台/Agent平台部"

# 5. 确认结果
nocode permission get <chatId>
```

### 场景 3：切换为外部公开

```bash
# 1. 查看当前权限
nocode permission get <chatId>

# 2. ⛔ 先向用户说明风险并获得明确确认：
#    「切换为外部公开后，非美团人员也能访问该页面，请注意信息安全。是否确认？」

# 3. 用户确认后执行
nocode permission set <chatId> EVERYONE

# 4. 告知用户需部署后生效
```

## ⚠️ 注意事项

- **权限配置与部署的关系**：权限变更后，已部署的作品会自动更新为最新权限配置；从未部署过的作品，权限配置会在首次手动部署时生效
- **非最新版本无法变更权限**：当前查看的不是最新版本时，权限控制不可修改，需先切换到最新版本
- **作品作者始终拥有访问权限**，不受白名单影响，也不可被移除
- **角标配置独立于链接分享权限**，两者互不影响，可单独设置
- 展示人员信息时使用 `displayName`（形如 `张三/zhangsan`）；展示部门时使用完整路径

## ⚠️ 常见错误

| 错误信息 | 处理方式 |
|---------|---------|
| `团队已设置「作品权限强制指定对象」` | **⛔ 禁止重试绕过。** 告知用户仅团队管理员/负责人可变更 |
| `有权限变更申请正在审批中` | **⛔ 禁止重试。** 告知用户等待审批完成后再操作 |
| `切换到外部公开需要审批` | 告知用户该变更需走审批流程，审批通过后自动生效 |
| `非最新版本，无法变更权限控制` | 提示用户先切换到最新版本 |
| `MIS 号不存在` | 用 `permission search-user` 确认正确的 MIS 号 |
| `search-org` 返回空数组 `[]` | **不是部门不存在，大概率是路径不完整。** 该接口不支持模糊关键词，必须传完整路径。**禁止换关键词重试**，应直接向用户索要完整部门路径 |
| `部门路径无效` | CLI 校验未通过，说明传的不是完整部门链。向用户索要完整路径，禁止自行拼接重试 |
| `部门权限写入失败（后端未保存）` | 部门链格式不被后端接受（常见于缺 `公司/` 前缀或路径有误）。用 `search-org` 取得 `name` 后原值重试 |
| `资源不存在` | 权限资源类型传错（作品权限固定为 `artwork`），或 chatId 不存在，确认 chatId 后重试 |
| `无权限操作` | 当前用户非作品所有者或管理者，需联系作品所有者操作 |
| `不能移除作品作者的权限` | 说明作品作者权限不可移除 |
| 权限已切换但访问仍是旧权限 | 提示用户需部署后生效，或等待已部署版本自动更新完成 |
