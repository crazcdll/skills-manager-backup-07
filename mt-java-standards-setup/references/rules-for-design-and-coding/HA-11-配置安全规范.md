# 配置安全规范

## 一、说明

本规范定义了配置管理的高可用标准，涵盖配置读取安全、开关管理和降级链三个领域。配置变更故障占 COE 的 10.4%，是仅次于代码逻辑脆弱的第二大故障诱因。一次错误的配置推送可能瞬间影响全部机器。

## 二、规则内容

### HA-CF001 [推荐] 配置读取建议有默认值和校验

所有从 Lion 等配置中心读取的配置建议有硬编码默认值，数值类配置建议有范围校验。

**说明**：
- 配置字段建议声明为 `volatile`（配置中心的回调是异步线程）
- 建议提供硬编码默认值，配置中心不可用时使用默认值
- 数值配置建议校验上下限，超出范围时保留旧值并告警
- JSON/复杂类型配置的解析建议 try-catch，解析失败时保留旧值
- 三级降级链：Lion 配置 > 本地缓存 > 硬编码默认值

### HA-CF002 [推荐] 开关建议标准化管理

功能开关建议使用 boolean 类型，默认关闭，通过 Lion 监听器实时生效。

**说明**：
- 开关命名：`{service}.{feature}.enabled`，值为 boolean
- 默认值建议为 `false`（关闭状态），通过配置中心打开
- 开关嵌套层级 ≤2 层，不建议深层嵌套（难以理解和测试）
- 功能稳定后（一般 2 个迭代周期），建议清理开关代码
- 开关变更建议有对应的监听器，确保实时生效

### HA-CF003 [推荐] 配置变更建议灰度推送

配置变更建议按灰度推送：1 台 → 观察 5min → 10% → 50% → 全量。

**说明**：
- 每步灰度后观察至少 5 分钟，确认核心指标无异常
- 配置变更建议有回调打点（记录变更时间、旧值、新值），便于排查
- 配置回调中不建议包含耗时操作（如 RPC、DB 查询），防止阻塞配置线程
- 配置变更建议可快速回滚（保留上一个版本的配置值）

### HA-CF004 [强制] 禁止使用指定的 banma_util 配置类

禁止使用 `banma_util` 包的 `BanmaMtConfigUtil` 和 `MtConfigClientFactoryV2`；配置读取必须使用 Lion Client API。

## 三、示例

以下示例仅用于说明规则边界与意图，不代表唯一实现方式；实际生成或审查代码时，应优先复用项目现有框架、工具类、SDK 与命名，并以是否满足规则约束为判断标准。

### HA-CF001 配置读取安全示例

#### good case:

```java
// volatile + 硬编码默认值 + 范围校验
@LionValue("${order.batch.size:100}")
private volatile int batchSize = 100; // 硬编码默认值

@LionListener("order.batch.size")
public void onBatchSizeChange(String newValue) {
    try {
        int value = Integer.parseInt(newValue);
        if (value < 1 || value > 1000) {
            log.warn("batchSize out of range: {}, keep old value: {}", value, batchSize);
            return; // 超出范围，保留旧值
        }
        this.batchSize = value;
    } catch (NumberFormatException e) {
        log.error("batchSize parse failed: {}, keep old value: {}", newValue, batchSize, e);
    }
}

// JSON 配置解析 try-catch
@LionListener("order.routing.config")
public void onRoutingConfigChange(String newValue) {
    try {
        RoutingConfig config = JSON.parseObject(newValue, RoutingConfig.class);
        this.routingConfig = config;
    } catch (Exception e) {
        log.error("routing config parse failed, keep old config", e);
        // 保留旧值，不更新
    }
}
```

#### bad case:

```java
// 无默认值 — 配置中心不可用时 NPE
@LionValue("${order.batch.size}")
private int batchSize; // 没有默认值

// 无范围校验 — 误配置为 0 或负数时系统异常
@LionListener("order.batch.size")
public void onBatchSizeChange(String newValue) {
    this.batchSize = Integer.parseInt(newValue); // -1? 0? 999999?
}

// 非 volatile — 其他线程可能看到脏值
private int batchSize = 100;
```

### HA-CF002 开关管理示例

#### good case:

```java
// boolean 开关，默认关闭
@LionValue("${order.newFlow.enabled:false}")
private volatile boolean newFlowEnabled = false;

public OrderResult processOrder(OrderRequest request) {
    if (newFlowEnabled) {
        return newOrderFlow(request);
    }
    return oldOrderFlow(request);
}
```

#### bad case:

```java
// 深层嵌套开关 — 难以理解和测试
if (featureAEnabled) {
    if (featureBEnabled) {
        if (featureCEnabled) {
            // 三层嵌套，哪种组合是预期的？
        }
    }
}
```

## 四、规范执行要点

- ✗ 不建议配置项无默认值 / 不用 volatile / 数值不做范围校验 / JSON 解析不 try-catch
- ✗ 不建议开关嵌套超过 2 层、过期未清理
