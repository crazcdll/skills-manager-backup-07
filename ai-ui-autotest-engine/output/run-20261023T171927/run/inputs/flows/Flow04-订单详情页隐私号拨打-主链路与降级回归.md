> 关联 EC 用例：4210290（P0：【订单详情页】隐私号拨打-主链路与降级-呼出正常）

> 前置条件：已预订国内酒店订单，联系酒店入口可用；含正常环境与取号失败环境两套数据；美团App / 点评App

## 落地入口

```
imeituan://www.meituan.com/mrn?mrn_biz=hotel&mrn_entry=hotelchannel-order-detail&mrn_component=hotelchannel-order-detail&order_id={order_id}&biz_type=1
```

## 场景 A · 正常环境立即呼叫

### S1. 点击联系酒店唤起呼出弹窗

**操作**：点击「联系酒店」。

**等待**：号码呼出弹窗展示。

**校验**：
- 「将使用该号码加密呼出」 — 渲染就绪标志
- 「双卡双待请确认，系统呼出号码和下方一致」 — 文案断言

### S2. 点击立即呼叫

**操作**：点击「立即呼叫」。

**等待**：系统拨号呼出（隐私号绑定呼出）。

**校验**：
- 呼叫正常发起（进入系统拨号界面） — 视觉确认

**接口断言**：`POST /hotelorder/v1/bindvirtualnumber.json`
- 绑定虚拟号成功后发起呼出

### A1. bindvirtualnumber 接口返回校验

- 接口 `POST https://apihotel.meituan.com/hotelorder/v1/bindvirtualnumber.json` 调用成功（error.code=200）
- 返回虚拟号码，呼叫链路正常发起

**证据要求**：截图或录屏记录呼叫发起（系统拨号界面）

## 场景 B · 取消关闭

**校验**：
- 「将使用该号码加密呼出」消失 — 文案消失
- 无异常弹窗或报错 — 视觉确认

## 场景 C · 取号失败降级直拨真实号

> 前置条件：本场景需取号失败环境（queryuserinfo 失败 Mock），Mock 规则由执行环境配置；无明确规则 ID 时不启用 Mock，标记人工准备。

### S1. 取号失败环境下点击联系酒店唤起弹窗

**操作**：点击「联系酒店」。

**等待**：弹窗展示（取号失败降级形态）。

**校验**：
- 弹窗展示 — 视觉确认

### S2. 点击立即呼叫验证降级直拨

**操作**：点击「立即呼叫」。

**等待**：系统拨号呼出。

**校验**：
- 降级场景直接呼叫酒店真实号码（非隐私号） — 视觉确认

**证据要求**：截图或录屏记录呼出号码形态，供人工确认降级直拨真实号
