# 物料检索规则

## 组件库优先级

**Max 组件 > Leez 组件**。优先选择 Max 组件，其次 Leez 组件，避免重复建设。

## 检索与决策规则

- 从需求分析中提取核心业务词（如「按钮」「标签」「半屏弹窗」「文字」等），在组件名称、描述、标签中进行中英文双向检索
- 结合图片与视觉稿，识别当前模块所需的布局模式（如「卡片 + 列表 + 筛选条件」等）
- 优先选择布局高度相似且可通过配置/皮肤满足需求的组件

## 检索流程

1. **环境检查（前置必做）**：执行 `duo --version` 确认 `@meishi/duo-cli` 已安装。若命令不存在，立即中断并提示：
   > ⚠️ 请先执行 `npm i -g @meishi/duo-cli --registry=http://r.npm.sankuai.com` 安装 duo-cli 后重试，安装前不得进行任何组件检索。

2. **理解需求与视觉**：阅读需求分析、图片与视觉稿分析结果，按模块列出需要支持的功能与布局模式

3. **拉取组件列表**：执行 CLI 命令 `duo component-list -t "leez,max"`，获取 Max、Leez 组件清单

4. **模块级初筛**：对每个需求模块，根据名称/描述/视觉结构筛出最合适的组件；遵守 Max > Leez 优先级

5. **获取组件详情（Props/API 的唯一合法来源）**：此步骤是填写 Props 字段的前提，**不得跳过，不得凭空猜测**：
   - 执行 CLI 命令 `duo component-read-detail -p "pkg1,pkg2,..."`，根据包名批量查询组件完整 Props/API 文档
   - **兜底方案**：上述命令返回空或报错时，通过 citadel skill 读取该组件对应的学城文档获取详细信息
   - 结合踩坑文档（学城 contentId `2749764228`）避免已知坑点
   - 若上述两种方式均无法获取，在对应 Props 字段标注 `待确认（未查到文档）`，**不得自行填写推测值**

6. **使用决策**：仅使用第 5 步查询到的真实 Props 和 API，根据组件使用规则和应用场景匹配情况决定是否使用该组件

7. **输出结果**：汇总模块与推荐组件的对应关系，每个组件须标注参数来源（"来自 duo component-read-detail" 或 "来自学城文档"）

## 图标处理优先级

1. **优先**从 Max/Leez 图标库检索可用图标组件（如 `leez-icon`），在推荐组件中标注图标名称与用法
2. **仅当**图标库无匹配项时，才使用视觉稿中的图片资源，并在 Mock 数据中提供图片 URL

## 执行要求

### 强制执行

- **必须首先执行 `duo --version` 检查环境**，`@meishi/duo-cli` 未安装时立即停止并输出安装指引
- 必须先执行组件检索，再给出结论；禁止在未检索或检索不充分的情况下直接给出开发结论
- 必须结合需求分析、视觉侧等上游输入做决策，不得只看其中一项
- 必须通过 `duo component-list -t "leez,max"` 拉取组件列表
- **必须通过 `duo component-read-detail -p "<pkg>"` 获取组件完整 Props/API 文档**；命令失败时才可降级到学城文档，不得直接跳过
- 必须遵守组件库优先级（Max > Leez）
- flex-design 文档中 Props 表格的所有字段（参数名、类型、默认值）**必须来自 duo CLI 或学城文档**，并在输出中标注来源

### 禁止执行

- **禁止在未执行 `duo --version` 环境检查的情况下开始任何组件检索**
- 禁止在未检索或检索不充分的情况下直接新建组件
- **禁止凭空猜测或推断组件 Props 名称、类型、默认值或用法**；一切 Props 信息必须来自 duo CLI 或学城文档
- 禁止忽略上游分析结果、仅凭单方面信息做决策
- **禁止在 Props 表格中填写"示例值"或"常见用法"等推测性内容**；查不到时统一标注 `待确认（未查到文档）`
