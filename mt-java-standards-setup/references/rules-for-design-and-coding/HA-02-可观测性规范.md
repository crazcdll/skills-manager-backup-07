# 可观测性规范

## 一、说明

本规范定义了系统可观测性的标准，涵盖 Metrics（指标）、Trace（链路）和 Alert（告警）三个支柱。可观测性是高可用的眼睛——没有观测能力，就无法发现问题、无法定位根因、无法验证恢复。

**日志级别使用、业务日志格式、traceId 透传、敏感信息脱敏等日志规范详见 `JAVA-06-日志记录规范.md`；日志 Appender 配置的高可用约束由本规范定义。**

## 二、规则内容

以下示例仅用于说明规则边界与意图，不代表唯一实现方式；实际生成或审查代码时，应优先复用项目现有框架、工具类、SDK 与命名，并以是否满足规则约束为判断标准。

### HA-O001 [推荐] Metrics 建议覆盖四黄金指标

所有对外提供的接口和核心内部方法建议覆盖四个黄金指标：延迟（Latency）、流量（Traffic）、错误率（Errors）、饱和度（Saturation）。代码中通过 Cat SDK 进行埋点，Raptor 作为大盘平台展示和告警。

**说明**：
- **埋点 SDK**：使用 `Cat.newTransaction()` 记录方法调用的耗时和成功/失败状态，使用 `Cat.logMetricForCount()` / `Cat.logMetricForDuration()` 记录自定义指标
- **命名规范**：Transaction name **不建议包含动态值**（如用户 ID、订单号），防止指标爆炸
- **大盘配置**：Raptor 大盘建议配置核心接口的 QPS、TP99、错误率、线程池利用率

#### good case:

```java
public OrderResult createOrder(OrderRequest request) {
    Transaction t = Cat.newTransaction("Service", "OrderService.createOrder");
    try {
        OrderResult result = doCreateOrder(request);
        t.setStatus(Transaction.SUCCESS);
        Cat.logMetricForCount("order.create.success");
        return result;
    } catch (Exception e) {
        t.setStatus(e);
        Cat.logMetricForCount("order.create.fail");
        throw e;
    } finally {
        t.complete();
    }
}
```

#### bad case:

```java
// Transaction name 包含动态值 — 导致指标爆炸
Transaction t = Cat.newTransaction("Service", "getUser_" + userId);

// 无任何 Metrics 埋点
public OrderResult createOrder(OrderRequest request) {
    return doCreateOrder(request); // 出问题了都不知道
}
```

### HA-O002 [推荐] Trace 建议支持全链路追踪

所有请求建议通过 Mtrace 自动透传 traceId，自定义异步操作建议手动传递 traceId。

**说明**：
- Mtrace 在 RPC 框架（OCTO/MTthrift）中自动透传，无需手动处理
- 自定义线程池需使用 TTL（TransmittableThreadLocal）或手动传递 Mtrace 上下文（详见 `HA-07` HA-J003）
- 自定义 span 的命名应清晰表达业务含义，如 `orderService.createOrder`
- 不建议在 span name 中使用动态值

---

### HA-O003 [推荐] 告警建议分级且有降噪策略

告警建议按优先级分级配置，并配置降噪策略防止告警风暴。

**说明**：
- P0 告警：核心链路不可用，建议 5 分钟内响应
- P1 告警：核心链路异常但可降级，15 分钟内响应
- P2 告警：非核心功能异常，1 小时内响应
- 告警降噪：同一告警 5 分钟内不重复发送；相关联的多个告警应聚合
- 告警内容建议包含：受影响的服务/接口、当前值与阈值、持续时间、快速定位链接

---

### HA-O004 [强制] 远程日志必须使用 AsyncScribe

远程日志上报必须使用 `AsyncScribe`，禁止将 `Async` 与 `Scribe` 组合使用，避免日志线程阻塞。

**说明**：
- 远程日志 Appender 的配置规范（`AsyncScribe` 用法、`blocking="false"`、禁止 `Async + Scribe` 组合）详见 `JAVA-06` N001，此处不重复定义
- 本条从可观测性高可用视角强调：错误的 Appender 配置会阻塞日志线程，导致日志丢失和线程耗尽，直接影响可观测性

### HA-O005 [强制] 生产环境禁止标准输出日志

生产环境禁止将日志输出到标准输出，禁止配置 `Console` Appender、`SYSTEM_OUT` 或 `SYSTEM_ERR`。

**说明**：
- `Console` 仅可用于本地调试
- 生产日志应输出到 `XMDFile` 或远程日志中心

#### good case:

```xml
<XMDFile name="infoAppender" fileName="info.log">
    <PatternLayout pattern="%d{DEFAULT} %-5p %msg%n%ex"/>
</XMDFile>
```

#### bad case:

```xml
<Console name="Console" target="SYSTEM_OUT" follow="true">
    <PatternLayout pattern="%d{DEFAULT} %-5p %msg%n"/>
</Console>
```

### HA-O006 [强制] 单条日志必须限制输出长度

`XMDFile` 的 `<PatternLayout>` 必须在 `pattern` 中限制消息输出长度，避免超长日志导致线程阻塞或 IO 负载过高。

**说明**：
- 可使用 `%.-524288msg` 将单条消息限制为 0.5 MB
- 长度上限应结合业务日志内容和存储容量评估

#### good case:

```xml
<XMDFile name="errorAppender" fileName="error.log">
    <PatternLayout pattern="%d{DEFAULT} %-5p %.-524288msg%n%ex"/>
</XMDFile>
```

#### bad case:

```xml
<XMDFile name="errorAppender" fileName="error.log">
    <PatternLayout pattern="%d{DEFAULT} %-5p %msg%n%ex"/>
</XMDFile>
```

### HA-O007 [强制] 异常堆栈必须使用简化格式

Appender 的 `<PatternLayout>` 必须包含 `%ex`，避免输出未简化的异常堆栈及依赖包信息。

**说明**：
- 对 `XMDFile`、`AsyncScribe` 等自定义 `PatternLayout` 均适用
- 异常对象仍应作为日志方法的最后一个参数传入

#### good case:

```xml
<AsyncScribe name="ScribeAsyncAppender" blocking="false">
    <PatternLayout pattern="%d{DEFAULT} %-5p %.-524288msg%n%ex"/>
</AsyncScribe>
```

#### bad case:

```xml
<AsyncScribe name="ScribeAsyncAppender" blocking="false">
    <PatternLayout pattern="%d{DEFAULT} %-5p %.-524288msg%n"/>
</AsyncScribe>
```

## 三、规范执行要点

- ✗ 不建议 Transaction name 包含动态值（用户ID、订单号等）
- ✗ 不建议核心接口无 Metrics 埋点就上线
- ✗ 不建议不配置告警就上线

### 代码审查检查点
- [ ] 核心接口是否有 Raptor Metrics 埋点
- [ ] Transaction name 是否包含动态值
- [ ] 异步操作是否正确透传 traceId（见 `HA-07` HA-J003 TTL）
- [ ] 是否配置了分级告警
- [ ] 远程日志是否使用 `AsyncScribe`，未使用 `Async + Scribe` 组合
- [ ] 生产环境是否移除了 `Console`、`SYSTEM_OUT` 和 `SYSTEM_ERR` 输出
- [ ] `XMDFile` 的 `PatternLayout` 是否限制了单条日志长度
- [ ] 自定义 `PatternLayout` 是否包含 `%ex`
