# 处置报告与记忆

## 前置输入（来自全流程前五步）

本 skill 作为全流程第六步执行，应已具备以下上下文：

| 输入项 | 来源 | 说明 |
|--------|------|------|
| 信号类型、业务线、Bundle/页面 | 第一步·信息提取 | 基本信息与原始信号 |
| 变更扫描结果 | 第二步·变更查询 | MCM/Diva 变更列表及相关度 |
| 止损操作记录 | 第三步·止损操作 | 操作类型、状态、时间、执行人；若跳过则包含原因 |
| 排查结论 | 第四步·排查结论 | 根因类型、日志证据、关联变更 |
| 修复方案 | 第五步·修复方案 | PR 链接 / traceId + 通知记录 / 待办 |

## 生成前置操作

在输出报告之前，**必须**先执行以下命令获取当前真实时间，用于填充报告中所有 `{生成时间}` 和第六步记录的时间戳：

```bash
date "+%Y-%m-%d %H:%M"
```

将命令输出结果（格式如 `2026-04-30 14:35`）赋值给 `REPORT_TIME`；严禁用会话上下文推断时间。

### 提取各步骤完成时间和耗时

**处置时间线中每步的完成时间和耗时必须从对应步骤的输出标题中提取，不得估算或推断。**

| 步骤 | 标题格式示例 |
|------|-------------|
| 第一步 | `✅ **第一步：信息提取结果**（完成时间：2026-04-30 14:23:05  耗时：约 3 分钟）` |
| 第二步 | `✅ **第二步：变更扫描结果**（完成时间：2026-04-30 14:28:12  耗时：约 5 分钟）` |
| 第三步（止损） | `🛑 **第三步：止损操作结果**（完成时间：2026-04-30 14:30:00  耗时：约 2 分钟）` |
| 第三步（跳过） | `🟢 **第三步：跳过止损**（完成时间：2026-04-30 14:28:15  耗时：约 1 分钟）` |
| 第四步 | `✅ **第四步【路径A】：告警排查结论**（完成时间：2026-04-30 14:46:33  耗时：约 18 分钟）` |
| 第五步 | `✅ **第五步：修复方案（xxx）**（完成时间：2026-04-30 14:56:59  耗时：约 1 分钟）` |

提取规则：

- **完成时间**：取 `完成时间：` 后的时间字符串；在报告中显示为 `HH:MM`。
- **耗时**：取 `耗时：` 后的字符串并原样填入。
- 缺失时填「—」，**严禁自行估算**。

## ⚠️ 严格格式要求

1. 报告必须严格按「问题总结」在前、「每一步详细结果」在后的顺序输出；不得将详细证据混入问题总结。
2. **【问题总结】必须使用完整表格**，每行一个字段，不得改成文字段落。
3. **【处置时间线】必须使用 5 列完整表格**（步骤 / 完成时间 / 耗时 / 操作内容 / 执行人），前五步各占一行。
4. **【每一步详细结果】必须按第一步至第五步依次直接引用前置 Skill 的完整输出**，不得二次提炼、改写、拆分字段、套用新模板或遗漏内容；即使止损跳过，也必须原样保留第三步的跳过结果。
5. 除报告标题、问题总结和处置时间线外，前五步内容保持其原有标题层级和 Markdown 格式。

## 反馈收集与写入处置记忆

报告生成后、写入记忆前，**必须向本次提问者收集反馈**，确认本次处置是否有效。使用明确的二选一提问：`本次稳定性排查是否有效？请选择「有效」或「无效」。`

收到反馈后，**无论结果为有效或无效，都必须写入记忆**。若提问者暂未反馈，先等待反馈，不得提前写入；若用户明确拒绝评价，按「未评价」写入记忆，并在标题中体现。

先读取 `memory` skill，并严格遵循其中的存储策略；稳定性处置经验属于本技能的领域知识，应优先追加到本技能的「学习笔记」。

### 记录原则

- 仅记录经排查确认、可复用于后续处置的事实：根因模式、关联变更特征、止损有效性、修复方案、排查证据和责任边界。
- 不记录完整告警原文、用户标识、订单号、traceId、敏感日志、密钥或临时链接。
- 用户标识如确需说明，使用脱敏摘要；不记录可回溯的个人信息。
- 每个问题追加一条独立记录；若结论为待确认，明确标注待确认项和后续验证条件。
- 标题必须包含提问者反馈标签：`【反馈：有效】`、`【反馈：无效】` 或 `【反馈：未评价】`；不得遗漏或使用其他表述。
- 反馈为「无效」时，仍完整记录本次根因、处置与失败/不符合预期的原因，并在复用建议中明确改进方向。

### 追加格式

在本 `SKILL.md` 末尾的 `## 学习笔记` 章节中追加以下内容；章节不存在时创建：

```markdown
### 【反馈：有效 / 无效 / 未评价】[{YYYY-MM-DD}] {业务线}｜{页面或 Bundle}｜{问题短标题}
- **提问者反馈**：{有效 / 无效 / 未评价；如有补充意见，使用脱敏摘要记录}
- **信号与影响**：{信号类型、影响范围的脱敏摘要}
- **根因**：{已确认根因；未确认时标注「待确认」及验证条件}
- **关联变更**：{Diva / MCM 变更对象与关联结论；无则写「未发现相关变更」}
- **止损与修复**：{是否止损、有效性、修复方式；不包含内部链接和敏感标识}
- **复用建议**：{下次优先检查的版本、组件、接口、监控或操作步骤；反馈无效时写明改进方向}
```

写入完成后，在最终回复中简短说明「已记录本次{有效 / 无效 / 未评价}处置经验」，不要展示或重复敏感信息。

## 报告完整性自查清单

- [ ] 报告先有「问题总结」，后有「每一步详细结果」
- [ ] 问题总结表格已填写问题定性、根因、影响、止损、修复和后续动作
- [ ] 处置时间线 5 列齐全，时间和耗时均取自各步骤标题；缺失字段填「—」
- [ ] 第一步至第五步详细结果已按顺序直接使用前置 Skill 的完整原始输出，未二次改写或套用新模板
- [ ] 第三步跳过时，已原样保留「跳过止损」输出；没有前置输出的步骤已明确标注未执行或未提供
- [ ] 变更、日志、异常、PR、通知与 trace 等证据均仅来自前置输出，未自行补写
- [ ] 未额外生成相关链接汇总、通知或通告，所有链接和证据均保留在对应的前置 Skill 原始输出中
- [ ] 已在写入记忆前向提问者询问本次处置是否有效
- [ ] 已收到「有效」或「无效」反馈后写入记忆；仅在明确拒绝评价时使用「未评价」
- [ ] 处置记忆标题已包含准确的「【反馈：有效】」「【反馈：无效】」或「【反馈：未评价】」标签
- [ ] 有效与无效的处置经验均已按脱敏原则追加到本技能「学习笔记」；无效记录已包含改进方向
