# 本地代码审查报告

> 用于独立运行，或上层明确要求完整前端报告的情况。受委托时默认按上层交接约定返回结果，不额外套用本模板；最终报告由上层组织。
> 需要落盘时，按章节顺序填写为单份 Markdown 文件。
> 准备章节（审查前输出）和发现章节（审查后输出）合并为一份报告，便于存档和模型能力评估。
>
> 注：如果可能，输出代码评审问题时，优先使用适合的特殊格式（如 catdesk 的 ::code-comment）

---

## 准备

**仓库**：`/path/to/repo`
**范围**：staged / working tree / `<base>...<head>` / commit `<sha>`（按实际填写）
**技术栈**：`max | duo | mrn | miniprogram | react`（可多选，自动识别）
**审查深度**：`quick` / `deep`
**规则来源**：记录本次 receipt 的 request_id / pull_id、L1/L2 snapshot、Release、交付模式、fallback 状态及诊断证据位置；附 L1/L2/L3 实际读取文件、入口来源、适用范围和已读章节，区分索引与正文；没有适用 L3 时注明未发现，无法读取时注明未读取。

> **未提交变更**：审查 staged / working tree 时纳入指定范围；审查 PR / commit / branch 时不混入工作区改动，如与结论有关则注明本轮未覆盖。
> **规则包排除**：`.mdp/rules/**` 与 `.fed/**` 为规则目录，不计入业务变更审查范围。

- **其它**：说明缺什么，中断并要求用户补全后再继续

## 审查概要

**生成时间**：YYYY-MM-DD HH:MM

- **变更摘要**：3～6 条要点，高层视角说明本次改动；第一条放最能代表本次变更意图的那句，其余按重要性递减，chore/纯技术类放最后
- **审查结论**（择一）：✅ 可合并 / ✅ 可合并（有优化建议）/ ⚠️ 修复后可合并 / ❌ 不建议合并
- **问题统计**：🔴 P0: _ / 🟠 P1: _ / 🟡 P2-P3: _
- **待确认**：_ 项（不计入 P0–P3）
- **上线风险**（根据变更范围及潜在影响，择一）：🟩 安全 / 🟨 低风险 / 🟧 中风险 / 🟥 高风险

> 有待确认问题时，在审查结论旁明确待核实条件；无缺陷不等于已排除风险。结论映射按 [output.md](output.md)。

## 发现项

> 按 P0 → P1 → P2-P3 分组；某组无问题写「暂无」。
> 按 [定级与证据判断](severity.md) 输出；P0/P1 说明触发条件、影响和证据，不保留低置信高级别候选。
> 命中规则时在问题类型后追加 `【规则：<source_type>/<scope_level> / <rule_set_id>@<rule_version> / <file>#<实际标题>】`，并填写 `rule_sources`。
> 纯上下文/业务逻辑判断使用空 `rule_sources`。

### P0（严重业务损害）

- 🔴 **[问题类型]【规则：platform/L1 / frontend-l1@release-1 / company/fe/前端规范/ASYNC.md#异步与异常处理】** `path:L行`：风险原因。建议：修复方案。
  - 依据：具体触发路径、受影响业务及严重后果；已核对现有保护。

### P1（高风险）

- 🟠 **[问题类型]** `path:L行`：风险原因。建议：修复方案。
  - 依据：触发条件、影响范围及已证实的功能损害。

### P2-P3（建议优化）

> 一行一条，可在问题类型前注明 `P2` 或 `P3`（不强制细分）。大量 ESLint / 格式问题合并为一条，建议运行 `eslint --fix`。

- 🟡 **[P2][问题类型]【规则：platform/L2 / team-fe@release-2 / team/fe/团队规范/L2-rules.md#请求约束】** `path:L行`：说明。建议：修复方案。

## 待确认问题（Open Questions）

> 按 [定级与证据判断](severity.md) 的准入条件筛选，无则写「暂无」；不计入缺陷数，不展示候选级别。
- **[Q-1] 问题标题** `path:L行`
  - **问题描述**：已观察到的代码行为或契约线索。
  - **不确定原因**：缺少的关键事实。
  - **可能的风险**：条件成立时的后果。
  - **确认建议**：应核对的位置或验证方式。

## 覆盖自评

- **已读**：diff 内文件 + 额外补读的文件/文档（与准备阶段计划对比，说明偏差）
- **未读 / 未验证**：（测试、联调、某目录仅扫过等）
- **补充建议**：仍需人工确认的部分
