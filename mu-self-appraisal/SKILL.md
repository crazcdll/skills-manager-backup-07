# mu-self-appraisal — 自评虾 🦐

管理主干 Skill 系列⑰

## 定位

> 帮员工把一年的付出变成一份让主管「看得见」的绩效自评——不是写流水账，而是用结构化方式讲清楚「做了什么、怎么做的、做到什么程度」。

**管理主干位置**：人才盘点 & 总体价值评价OV 模块

**上下游关系**：
- ⬆️ 上游：mu-work-summary（述职材料可复用）、目标管理系统（hrskills 内置，Step 0 自动采集）
- ➡️ 同级：mu-review-feedback（绩效评价，For 管理者/HRBP）
- ⬇️ 下游：mu-talent-review（人才盘点会和OV校准）

## 触发说明

用户提到以下关键词时激活：绩效自评、自评、写自评、绩效总结、工作回顾、个人总结、年度考核、OV自评、**季度自评、半年自评、Q1/Q2/Q3/Q4自评、H1总结、H2自评、上半年总结、下半年总结**。

**不激活**：绩效评价/校准（管理者视角）、目标设定、述职材料撰写。

## Step 0：目标数据自动采集（所有模式强制执行）

> 触发后第一件事：通过 `hrskills teamgoal` 自动拉取用户的目标清单，作为重点工作的锚。
> **不需要用户提供，不需要安装额外 Skill。**

### MIS 获取规则

优先从当前会话上下文取用户 MIS；取不到时，在执行采集前问用户：「请告诉我你的 MIS（工号），用于查询目标系统」。

### 采集流程

```bash
# 1. 检查/安装 hrskills
npm list -g @block/hrskills --depth=0 2>/dev/null | grep hrskills \
  || npm install -g @block/hrskills --registry=http://r.npm.sankuai.com

# 2. 拉取个人目标清单
env HTTP_PROXY="" http_proxy="" HTTPS_PROXY="" https_proxy="" \
  hrskills teamgoal query-list --queryMyGoalList true --mis <用户MIS>

# 3. 根据 listCode 拉取清单下的目标（含进展）
env HTTP_PROXY="" http_proxy="" HTTPS_PROXY="" https_proxy="" \
  hrskills teamgoal query-goal \
  --queryCondition '{"moduleList":["GOAL","PROGRESS"],"listCode":"<listCode>"}' \
  --mis <用户MIS>
```

**采集后处理**：
- 展示目标列表（编号 + 标题 + 链接），让用户确认「这些就是你的目标吗？」
- 用户确认后，以目标条目为骨架撰写重点工作（每条目标对应一条工作回顾）
- 超出目标的额外工作，作为加分项附在主目标之后，并计入 2~5 条总数限制

### 降级链

| 场景 | 处理方式 |
|------|----------|
| hrskills 未安装 / 安装失败 | 自动执行 `npm install -g @block/hrskills --registry=http://r.npm.sankuai.com` 后重试 |
| 认证失败（需手机确认） | 提示用户在大象 App 点击确认，确认后自动重试 |
| MIS 未知 / 取不到 | 在采集前直接问用户：「请告诉我你的 MIS（工号），用于查询目标系统」 |
| 目标清单为空 / 接口超时 | 告知用户未查到目标，询问是否手动提供；手动提供则按快速/引导模式继续 |
| 用户明确说「不用查目标」 | 跳过 Step 0，直接进入对应交互模式 |

## 交互模式

### 🚀 快速模式

用户已有材料（述职、周报、去年自评等），直接转化。

> 目标数据已由 Step 0 自动采集。快速模式以用户提供的材料为主，目标结果作补充参考；两者冲突时以用户材料为准。

**进入条件**：用户提供了材料链接/文件/文本，或说"帮我把述职转成自评"。

**流程**：
1. 读取材料 → 2. 提取重点工作（≤5条）→ 3. 按 STAR 结构化每条 → 4. 生成个人总结框架 → 5. 质检 → 6. 输出

**门控条件**：
- Step 2 → Step 3：材料内容不足以提取任何重点工作时，停留在 Step 2 追问用户补充；至少提取到 1 条才进入 Step 3
- Step 3 → Step 4：若某条工作缺少结果数据，标记 `[待补充]` 并继续，不阻断流程
- Step 5 → Step 6：三道质检必须全部完成，不可跳过

### 💬 引导模式

用户从零开始，不知道写什么。

> 目标数据已由 Step 0 自动采集。引导模式直接以目标条目为起点引导用户阐述每项目标的顶层内容。

**进入条件**：用户说"帮我写自评"但没有提供材料，或说"不知道写什么"。

**流程**：
1. 收集基本信息 → 2. 逐条引导重点工作 → 3. 引导个人总结 → 4. 质检 → 5. 输出

**门控条件**：
- Step 1 → Step 2：必填项（岗位/身份）未齐全时，停留在 Step 1 追问，不进入 Step 2；Step 0 已有目标则以目标为起点，无目标时补问「最值得说的2~5件事关键词」；选填项（成长/不足/展望）缺失可继续，用 `[待补充]` 占位
- Step 2 → Step 3：用户仅提供关键词而无结果数据时，每条工作最多追问 1 次，用户仍未补充则标记 `[待补充]` 继续，不卡死
- Step 3 → Step 4：个人总结部分至少完成「整体工作表现」和「优势/待提升项」两块，展望可为空
- Step 4 → Step 5：三道质检必须全部完成

## 信息收集清单

### 快速模式（材料转化）

```
1. 已有材料来源（以下任意一项或多项）：
   - 述职文档链接/文件
   - 周报/月报汇总
   - 去年自评内容
2. 身份：个人贡献者 / 一线经理 / MM及以上（影响团队建设部分的范围）
3. 对自己本周期表现的整体感受（一句话）
4. 有没有特别想强调或补充的工作
```

### 引导模式（从零开始）

```
【必填项（缺一不可，缺少则追问）】
1. 你的岗位和职级大概是什么（不用精确，了解工作性质即可）
2. 身份：个人贡献者 / 一线经理 / MM及以上
3. 过去这段时间最值得说的2~5件事是什么（关键词就行，至少2件）【Step 0 已有目标时跳过此项，直接以目标为骨架】

【选填项（缺失时标[待补充]，不阻断流程）】
4. 每件事的大致背景和结果
5. 你觉得自己最大的成长是什么
6. 有什么地方觉得做得不够好
7. 接下来想做什么/想往哪个方向发展
```

**最小信息集**：完成条目 1、2、3 即可启动写作；条目 4~7 缺失时，对应位置标 `[待补充]` 提示用户事后补全。

## 工作回顾撰写规范

每条重点工作按以下结构输出：

### STAR 结构模板

```
【重点工作N】<一句话说清楚做什么事、达成什么目标>
完成情况：超出预期 / 达成预期 / 不及预期

具体描述：
· 情景/任务：<什么背景下，面临什么挑战/要求>
· 行动：<采取了什么关键措施，怎么做的>
· 结果：<实现了什么成果，用数据/事实说明>
```

**重点工作/目标的写法**：
- ❌ 短标题：「高端人才引进」「组织诊断」
- ✅ 完整表述：「聚焦大模型训练/具身智能/AI Infra三个方向，完成关键高端人才引进」
- ✅ 完整表述：「主导<团队>AI变革组织诊断，输出<N>人方向调整路线图」
- 像写团队目标（TG）一样——一句话包含「做什么事」+「达成什么目标/结果」

**撰写要点**：
- 重点工作控制在 **2~5条**，聚焦最有价值的产出，不要事无巨细
- 每条描述 **150~300字** 为宜，太短没说服力，太长失去焦点
- **必须有结果**：不能只写"做了什么"，要写"做到了什么程度"
- 数据优先：能量化的量化（完成率、提升比例、节省时间等）
- 完成情况的等级要**诚实**：自评是给主管的沟通窗口，不是自我吹嘘

### 管理者额外部分：团队建设

管理者在工作回顾中额外增加一条「团队建设」，按管理层级区分：

**所有管理者必答（含一线经理）：**
1. 团队分工是否合理、有序？跨团队合作是否顺畅高效？
2. 在人才"进出上下换"方面做得如何？（招聘、人才培养与保留、汰换等）

**MM（Managing Managers，管理管理者）及以上额外回答：**
3. 在组织调优和提效上做了哪些工作？
4. 在人才梯队建设方面做了哪些工作？

> 判断是否为MM：如果下属中有管理者（带团队的人），就是MM。一线经理只需回答1、2。

## 个人总结撰写规范

### 三段式结构

```
【整体工作表现】
对本周期工作的概括性总结，2~3句话点明整体状态和核心成果。

【个人优势项和待提升项】
优势（2~3条）：
1. <具体行为描述，可对照领导力原则>
2. ...

待提升项（2~3条）：
1. <具体不足，附带改进方向>
2. ...

【未来展望】
工作展望：明年的工作重点和目标方向
个人展望：自身成长发展期望，希望承担的角色/工作类型
```

**撰写要点**：
- 优势和不足都要**具体+行为化**，不要"沟通能力强"这种空话
- 可参考美团领导力原则（LP）来对照，也可以写 LP 以外的内容
- 未来展望要**可落地**：有明确方向和初步计划，便于与主管对齐
- 优势和待提升项数量大致平衡（不要写5个优点1个缺点）

## 质检流程

完成初稿后，依次执行三道质检：

### 第一道：Bad Case 检测

逐条扫描，发现以下模式立即标记并建议修改：

| Bad Pattern | 问题 | 修改方向 |
|-------------|------|---------|
| "我认为本周期工作达到了预期" | 缺案例支撑 | 补充具体事例和数据 |
| "我组织的X活动顺利开展了" | 一句话略过 | 展开 STAR 结构 |
| "我感到非常的xxx，学会了xxx" | 只聊心得 | 聚焦客观产出和结果 |
| "积极主动地参与各种项目" | 空话套话 | 换成具体项目+具体贡献 |
| "觉得还不错，继续加油" | 敷衍总结 | 分维度展开优势/不足/展望 |

### 第二道：结构完整性检查

- [ ] 重点工作 2~5 条，每条有 STAR 结构
- [ ] 每条都有完成情况等级
- [ ] 管理者包含团队建设部分（一线经理≥2项，MM及以上≥4项）
- [ ] 个人总结含三个模块（整体/优势不足/展望）
- [ ] 优势和待提升项数量大致平衡
- [ ] 未来展望有明确方向

### 第三道：AI味消除

调用 mu-humanizer-minesweeping 对全文进行去 AI 腔处理。自评是写给主管看的，必须是自己的话，不能像 AI 生成的模板。

**降级策略**：若 mu-humanizer-minesweeping 不可用，由 Agent 自行执行去 AI 腔检查——扫描以下模式并替换：「显著提升/有效推进/深度赋能」等管理黑话、句式千篇一律的排比结构、缺乏主语的被动句。

### 使用建议

输出到学城文档后，提醒用户：
1. 通读一遍，用自己的话润色（自评最忌讳完全模板化）
2. 核对数据是否准确（数字、时间、项目名称）
3. 复制到 ov.sankuai.com 系统提交
4. 提交前可让信任的同事或HRBP帮忙看一眼

## 硬规则

> **IRON LAW 1**：重点工作必须 2~5 条，超过 5 条要求用户合并或砍掉最次要的
>
> **IRON LAW 2**：每条工作回顾必须有结果描述，"做了什么"不等于"做到了什么"
>
> **IRON LAW 3**：禁止替用户编造工作内容或数据——没有的就标 `[待补充]`，让用户自己填
>
> **IRON LAW 4**：管理者身份必须包含团队建设部分（一线经理答1、2；MM及以上答1~4），不能跳过
>
> **IRON LAW 5**：输出前必须过三道质检（Bad Case检测 + 结构完整性 + AI味消除），不能跳步
