# 学城 CR 文档结构模板

> ⚠️ 本模板描述最终文档结构。实际文档由 `publish_results.py` 脚本拼装，主 Agent 只需产出结构化输入文件（Issue JSON、summary MD、SDD MD 等），不需要手写文档正文。
> 章节四（Review 发现）的 Issue 部分由脚本从统一 Issue JSON 自动拼装，不区分 Step 4-A / Step 4-B 来源。

# PR #{id} Code Review：{标题}

> 注：上面是文档正文的大标题（保持不变）。学城目录树上的【文档标题】由 publish_results.py 生成，
> 学城文档标题包含仓库和本轮唯一标识：`{org}/{repo} PR #{id} Code Review {run_id}：{标题}`。`run_id` 每轮生成一次 UUID，同轮重试复用，不同轮次必须不同。

## 一、PR 概述

| 项目 | 内容 |
|------|------|
| 仓库 | {org}/{repo} |
| PR 编号 | #{id} |
| 标题 | {标题} |
| 提交人 | {authorName}（{submitter_mis}） |
| 触发人 | {triggerName}（{triggerMis}） |
| 分支 | {sourceBranch} → {targetBranch} |
| 文件数 | {fileCount} |
| 行数变化 | +{additions} / -{deletions} |
| 审查时间 | {cr_at} |
| 审查范围 | {scope_label} |
| 覆盖缺口（可选） | ⚠️ {N} 个文件 diff 拉取失败，本次审查未覆盖 |
| Skill 版本 | {skill_name} {skillhub.version} |

> **覆盖缺口**行仅在 mode_info 的 `failedFiles` 非空时追加（由 `publish_results.py` 自动处理），清单见 PR 全局评论末尾。Agent 不得隐瞒或删除。

> **Skill 版本**字段格式：`{skill_name} {skillhub.version}`，值从 SKILL.md 头部 metadata 中的 `name` 和 `skillhub.version` 字段拼接而成。
> 示例：`ai-quality-cr-agent V40`
>
> **审查范围**字段：位置固定在「行数变化」之后、「Skill 版本」之前（对应 `publish_results.py` 中 `overview_rows.append(("审查范围", scope_label(args)))`）。
> 由 `scope_label(args)`（**非 compact** 形式，与大象推送的紧凑形式不同）生成，取值如下：
>
> | 场景 | 实际输出 |
> |------|---------|
> | 全量 CR | `🟦 全量` |
> | 增量 CR | `🟩 增量（从 \`7394fa3d\` → \`57c84425\`，5 个新 commit）` |
> | 增量但 base/target 缺失 | `🟩 增量（5 个新 commit）` |
> | 增量但无任何信息 | `🟩 增量` |
>
> commit hash 取前 8 位展示（`_short_hash()`）。该行始终输出，不会因为是全量 CR 而省略。
>
> 示例（全量）：`| 审查范围 | 🟦 全量 |`
> 示例（增量）：`| 审查范围 | 🟩 增量（从 \`7394fa3d\` → \`57c84425\`，5 个新 commit） |`

## 四、Review 发现

> ⚠️ 本章节由 `publish_results.py` 从统一 Issue JSON 自动拼装，**不区分 Step 4-A / Step 4-B 来源**。所有 issue 按 severity 分组（P0 → P1 → P2 → P3），组内统一编号 `[P0-1] [P0-2] [P1-1] ...`，去重后合并展示。

### 规则命中摘要

> 本项 CR 激活的审查规则及命中情况一览，检出细节见下方各 P 层级。

**激活信号**：{SIG-CONCURRENCY, SIG-SQL, ...}（来自 Step 3E）

**命中规则综述**：本次审查共发现 {total_hits} 个问题，涉及 {total_rules} 条去重规则。问题数与规则标签命中数分别统计；一个问题可带多条规则。

- **P0 零容忍**：命中 {p0_count} 条 — {命中的 P0 规则编号列表}
- **P1 稳定性**：命中 {p1_count} 条 — {命中的 P1 规则编号列表}
- **P2 规范**：命中 {p2_count} 条 — {命中的 P2 规则编号列表}
- **P3 性能**：命中 {p3_count} 条 — {命中的 P3 规则编号列表}
- **待确认**：{confirm_count} 个问题，等待人工补充证据后定级

规则标签命中：CR: {cr_hit} / MT: {mt_hit} / CU: {cu_hit} / BL: {bl_hit} / FE: {fe_hit} 次；无规则标注 {unlabeled_count} 个问题。未命中的规则不再逐一列出。

> **规则编号前缀规范**：保留真实 `CR:` / `MT:` / `CU:` / `BL:` / `FE:` 规则；FE 结果在主 Agent 结果转换阶段统一添加 `FE:` 前缀，脚本幂等兜底。L3 规则优先使用文件定义的 ID（`FE:L3_<id>`），没有定义 ID 时使用 `FE:L3_custom`；纯上下文判断没有规则编号时才留空，展示为「无规则标注」。
> **同时命中 CR: 和 MT: 规则时写 `[CR:xxx] + [MT:yyy]`**（加号连接，CR: 在前 MT: 在后）。
> ⚠️ 同一问题同时命中 CR: 和 MT: 规则时，两个编号都列出。
