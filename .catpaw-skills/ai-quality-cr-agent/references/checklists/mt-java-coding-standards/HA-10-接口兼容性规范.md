# 接口兼容性规范

## 一、说明

本规范定义了接口变更的兼容性标准，涵盖字段变更规则、序列化安全和版本管理三个领域。接口兼容性故障占 COE 的 9.4%，是高可用体系中极易被忽视但影响巨大的领域。一次不兼容的接口变更可能导致所有调用方解析失败。接口结构设计（命名/参数/返回值/幂等）见 `JAVA-08`，其 java-l1:HA-10.N007 为本规范的接口设计侧入口。

## 二、规则内容

### java-l1:HA-10.HA-API001 [推荐] 字段变更建议向后兼容

接口响应中的字段变更建议保证向后兼容：不建议删除已有字段、不建议修改字段类型。

**说明**：
- **不建议直接删除字段**：先标记 `@Deprecated`，通知所有调用方迁移，确认无调用后再删除（至少保留 2 个迭代周期）
- **不建议直接修改字段类型**：通过新增字段 + 双写过渡，旧字段标记 `@Deprecated`
- **新增字段建议是 optional**：新增字段建议有默认值，不建议影响已有调用方
- **枚举类型建议包含 default 分支**：消费方的 switch/case 建议有 default，防止新增枚举值导致异常

### java-l1:HA-10.HA-API002 [推荐] 序列化建议安全配置

JSON/Thrift/Protobuf 的序列化配置建议容忍未知字段。

**说明**：
- Jackson：`FAIL_ON_UNKNOWN_PROPERTIES` 建议设为 `false`
- Jackson：使用 `@JsonIgnoreProperties(ignoreUnknown = true)` 注解
- Thrift IDL：字段建议标记 `optional`，字段 ID 不可变，不可复用已删除字段的 ID
- Protobuf：使用 `reserved` 保护已删除字段的编号，不建议复用编号
- 接口请求和响应建议使用独立的 DTO，不建议直接暴露内部领域模型

### java-l1:HA-10.HA-API003 [推荐] 接口版本管理建议有序

接口变更建议按版本管理，新旧版本共存至少 2 个迭代周期。

**说明**：
- 大版本变更（不兼容变更）建议使用新的接口路径或版本号
- 灰度发布按调用方逐步切流，不建议一次性全量切换
- 版本切换前建议确认所有调用方已适配

### java-l1:HA-10.HA-API004 [强制] Thrift IDL 变更必须保持向后兼容

对已发布的 Thrift IDL，禁止修改或删除已有服务名、方法名和字段；字段 ID、枚举值必须保持唯一且不可变。`optional` 字段禁止改为 `required`，存量结构体新增字段必须使用 `optional`。

**说明**：
- 禁止修改或删除已有服务名、方法名；需要调整时必须新增服务或方法替代旧定义
- 禁止修改或删除已有字段，禁止修改字段 ID；新增字段不得复用已删除字段的 ID
- 枚举值必须唯一；新增枚举值必须使用未占用的值，不得修改已有枚举值
- 禁止将已有 `optional` 字段修改为 `required`；该变更会使未升级调用方因未传字段而调用失败
- 存量结构体新增字段必须标记为 `optional`，避免未升级调用方序列化或反序列化失败

#### good case:

```thrift
service OrderService {
    Order getOrder(1: i64 orderId)

    // 新增方法替代原有方法，不修改或删除 getOrder
    Order getOrderV2(1: i64 orderId, 2: optional bool withDetail)
}

enum OrderStatus {
    PENDING = 1,
    COMPLETED = 2,
    CANCELED = 3 // 使用未占用的枚举值新增
}

struct Order {
    1: required i64 orderId,
    2: optional string status,
    3: optional string remark // 存量结构体新增字段必须 optional
}
```

#### bad case:

```thrift
service OrderService {
    // 删除或改名已有 getOrder，未升级调用方会调用失败
    Order queryOrder(1: i64 orderId)
}

enum OrderStatus {
    PENDING = 1,
    COMPLETED = 1 // 枚举值重复
}

struct Order {
    1: required i64 orderId,
    2: required string status // 原 optional 字段改为 required
    // 删除已有字段或修改字段 ID 也会破坏兼容性
}
```

## 三、实践建议

1. 接口变更前建议评估向后兼容性
2. Thrift IDL 变更必须保持服务、方法、字段 ID 与枚举值兼容
3. Thrift 存量结构体新增字段必须为 optional，已有 optional 字段不得改为 required
4. Jackson FAIL_ON_UNKNOWN_PROPERTIES 建议为 false
5. 不兼容变更建议灰度发布

## 四、示例

以下示例仅用于说明规则边界与意图，不代表唯一实现方式；实际生成或审查代码时，应优先复用项目现有框架、工具类、SDK 与命名，并以是否满足规则约束为判断标准。

### java-l1:HA-10.HA-API001 字段变更示例

#### good case:

```java
// 正确的字段变更流程
public class OrderResponse {
    private Long orderId;

    @Deprecated // Step 1: 标记废弃，通知调用方迁移
    private String oldStatus;

    private Integer statusCode; // Step 2: 新增字段替代

    // 双写过渡
    public void setStatusCode(Integer code) {
        this.statusCode = code;
        this.oldStatus = StatusEnum.of(code).name(); // 同时写旧字段
    }
}

// 枚举消费时建议有 default
switch (status) {
    case PENDING: handlePending(); break;
    case COMPLETED: handleCompleted(); break;
    default: handleUnknown(status); break; // 防止新增枚举值导致异常
}
```

#### bad case:

```java
// 直接删除字段 — 调用方反序列化可能异常
public class OrderResponse {
    private Long orderId;
    // private String status; // 直接删了！调用方可能还在用
    private Integer statusCode;
}

// 直接修改字段类型 — 调用方反序列化失败
public class OrderResponse {
    private Long orderId;
    private Integer status; // 原来是 String，直接改成 Integer
}
```

### java-l1:HA-10.HA-API002 序列化安全示例

#### good case:

```java
// Jackson 全局配置
objectMapper.configure(DeserializationFeature.FAIL_ON_UNKNOWN_PROPERTIES, false);

// DTO 注解
@JsonIgnoreProperties(ignoreUnknown = true)
public class OrderDTO {
    private Long orderId;
    private String status;
}
```

#### bad case:

```java
// 默认配置 — 新增字段会导致反序列化失败
ObjectMapper mapper = new ObjectMapper(); // FAIL_ON_UNKNOWN_PROPERTIES 默认 true

// 直接暴露领域模型 — 内部变更直接影响外部调用方
@GetMapping("/order/{id}")
public Order getOrder(@PathVariable Long id) {
    return orderRepository.findById(id); // Order 是数据库实体，不是 DTO
}
```

## 五、规范执行要点

### 推荐要点
1. **字段变更**：不建议删除/改类型，新增建议 optional 有默认值，枚举建议 default
2. **序列化**：FAIL_ON_UNKNOWN_PROPERTIES=false，Thrift 用 optional，Protobuf 用 reserved
3. **版本管理**：新旧共存 ≥2 个迭代周期，按调用方灰度切流

### Thrift 强制要点
1. **服务与方法**：禁止修改或删除已发布的服务名、方法名
2. **字段**：禁止修改或删除已有字段和字段 ID；存量结构体新增字段必须为 optional，已有 optional 不得改为 required
3. **枚举**：枚举值必须唯一，已有枚举值不可修改，新增值必须使用未占用的值

### 不建议做法
- ✗ 不建议直接删除已有字段
- ✗ 不建议直接修改字段类型
- ✗ 不建议 FAIL_ON_UNKNOWN_PROPERTIES 为 true
- ✗ 不建议 Thrift 字段不标 optional
- ✗ 不建议复用已删除字段的 ID/编号
- ✗ 不建议直接暴露领域模型作为接口响应
- ✗ 不建议不兼容变更一次性全量切换
- ✗ 禁止修改或删除已发布的 Thrift 服务名、方法名、字段或字段 ID
- ✗ 禁止 Thrift 枚举值重复或修改已有枚举值
- ✗ 禁止将已有 Thrift optional 字段改为 required
- ✗ 禁止为存量 Thrift 结构体新增 required 字段

### 代码审查检查点
- [ ] 接口变更是否向后兼容
- [ ] 删除的字段是否走了 @Deprecated 流程
- [ ] 新增字段是否 optional 且有默认值
- [ ] 枚举消费是否有 default 分支
- [ ] Jackson 是否配置了 FAIL_ON_UNKNOWN_PROPERTIES=false
- [ ] 接口响应是否使用独立 DTO
- [ ] Thrift 服务名、方法名、字段和字段 ID 是否未被修改或删除
- [ ] Thrift 枚举值是否唯一，且已有枚举值未被修改
- [ ] Thrift 存量结构体新增字段是否为 optional，已有 optional 字段是否未改为 required
