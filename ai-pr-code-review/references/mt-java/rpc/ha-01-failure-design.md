## HA-01 失败设计规范（审查精要）

| 编号 | 规则 | 级别 |
|------|------|------|
| MT:HA-F001 | 所有RPC/HTTP/DB/缓存调用必须显式设置超时，禁止依赖框架默认值 | P1 |
| MT:HA-F002 | 重试必须满足：幂等性保证+指数退避+随机抖动+最大次数限制(≤3次) | P1 |
| MT:HA-F003 | 熔断必须使用Rhino平台，禁止自行实现；必须配置fallback | P1 |
| MT:HA-F004 | 降级开关必须boolean+Lion管理+默认关闭+独立路径+有业务含义的返回值 | P1 |
| MT:HA-F005 | 核心接口必须配置限流（Rhino平台+Token Server兜底），返回429非500 | P1 |
| MT:HA-F006 | 弱依赖失败不能阻断主流程，必须try-catch+降级+告警+独立线程池隔离 | P1 |

### 强制禁止
- ✗ 禁止依赖框架默认超时
- ✗ 禁止固定间隔重试（会导致重试风暴）
- ✗ 禁止写操作在未保证幂等时重试
- ✗ 禁止自行实现熔断（必须使用 Rhino）
- ✗ 禁止 fallback 中再调用可能失败的外部依赖
- ✗ 禁止弱依赖失败阻断主流程
- ✗ 禁止降级返回空值或异常（必须有业务含义）
- ✗ 禁止核心接口不配置限流就上线
- ✗ 禁止多依赖共用同一个线程池/HttpClient

### 检查点
- [ ] 所有 RPC/HTTP 调用是否显式设置超时
- [ ] 重试逻辑是否满足幂等+退避+次数限制
- [ ] 核心链路是否接入 Rhino 熔断
- [ ] 熔断 fallback 是否可用且不依赖外部服务
- [ ] 降级开关是否通过 Lion 管理
- [ ] 弱依赖是否做了隔离和降级处理
- [ ] 核心接口是否配置了限流
- [ ] 限流 fallback 是否返回有意义的结果（非500）
