# 防御性编程规范

## 一、说明

本规范定义了防御性编程的高可用标准，涵盖参数校验、空指针防御、异常分类处理三个领域。防御性编程是系统韧性的第一道防线——在数据和状态到达业务逻辑之前，就把不合法、不安全的输入拦截掉。

本规范的关注维度是"如何从高可用角度做好输入防御和资源保护"，与 JAVA-05 异常处理规范（关注"异常机制的正确使用方式"）形成互补。

## 二、规则内容

### HA-D001 [推荐] 参数建议前置校验

所有外部输入（RPC 参数、HTTP 参数、MQ 消息体）建议在方法入口进行校验，校验失败时抛出明确的业务异常。

**说明**：
- 使用 `Preconditions.checkArgument()` / `Preconditions.checkNotNull()` 进行前置校验
- Controller 层使用 `@Validated` + `@NotNull` / `@Size` 等 JSR-303 注解
- 校验失败应抛出 `IllegalArgumentException` 或自定义 `BizException`，不建议返回 null 或空对象掩盖错误
- 数值参数建议校验上下限，防止异常值穿透到下游

### HA-D002 [强制] 外部返回值和级联调用必须防御空指针

使用 Thrift、RDS、Cellar、Squirrel 返回对象或 Mafka 消费对象前必须判空；禁止未判空的级联调用。语义上返回基本类型的方法必须直接返回基本类型；如返回包装类型，使用前必须判空，避免自动拆箱触发空指针异常。

**说明**：
- Thrift、RDS、Cellar、Squirrel 的返回对象在访问属性或调用方法前必须判空
- Mafka 消费对象在读取消息内容前必须判空
- 禁止直接编写 `obj.getA().getB().getC()` 等未判空的级联调用；可使用 `Optional` 完成链式空值处理
- 对外声明返回值为基本类型语义的方法，不得使用包装类型替代；确需返回包装类型时，调用方必须在自动拆箱前判空

### HA-D003 [推荐] 异常建议分类处理

业务异常（BizException）与系统异常（SystemException）建议明确分离，走不同的处理路径。

**说明**：
- **业务异常**（参数校验失败、库存不足、余额不足）：返回明确错误码，不触发熔断和告警
- **异常捕获语法与返回值规范见 `JAVA-05`**：本条按「业务异常/系统异常」分类决定触发策略（熔断/告警/降级）；JAVA-05 聚焦异常怎么写（捕获范围、返回值避免 null）。两者配合：先按 HA-D003 判断异常类型选择处理路径，再按 JAVA-05 规范捕获与返回。
- **系统异常**（RPC 超时、DB 连接失败、OOM）：触发熔断计数，触发告警，走降级路径
- 全局异常处理器（`@ControllerAdvice`）建议区分两类异常的处理逻辑
- 异常链建议保留：`throw new BizException("msg", e)` 而非 `throw new BizException("msg")`
- 不建议空 catch（`catch (Exception e) {}`），每个 catch 建议有日志或处理逻辑

### HA-D004 [推荐] 资源建议安全释放

所有需要释放的资源（数据库连接、文件流、HTTP 连接）建议使用 try-with-resources 或在 finally 中释放。

**说明**：
- 优先使用 try-with-resources（实现 `AutoCloseable` 的资源）
- 连接池资源（数据库连接、Redis 连接）建议确保归还，不建议泄漏
- HTTP 连接建议设置连接池上限和空闲超时
- finally 中释放资源时，释放操作本身的异常不建议覆盖原始异常

### HA-D005 [强制] 日期格式化必须使用日历年

日期格式化必须使用日历年 `yyyy`，禁止使用周基年份 `YYYY`，避免年末跨周时格式化年份错误。

### HA-D006 [强制] LocalDateTime 计算必须使用时间 API

禁止对 `LocalDateTime` 的 `getDayOfMonth()`、`getDayOfYear()`、`getMonthValue()`、`getHour()`、`getMinute()`、`getSecond()`、`getYear()`、`get(TemporalField)`、`getLong(TemporalField)`、`lengthOfMonth()` 返回值进行手工加减运算；日期时间计算必须使用对应的 `plus*` 或 `minus*` 方法。

### HA-D007 [强制] 循环必须有明确边界和有效逻辑

禁止使用 `while (true)` 或 `for (;;)`；循环前必须校验数组或集合对象非空，循环索引不得越界，循环体不得为空。增强型 `for` 遍历集合时，禁止直接调用该集合的 `add()`、`remove()` 等结构性修改方法。

**说明**：
- 循环应使用可验证的退出条件；确需复杂循环控制时，必须封装为独立方法，并具备最大循环次数或异常监控等保护
- 遍历数组或集合前必须判空；索引必须满足 `0 <= index < length/size()`
- 禁止误写循环体后的分号或编写无业务效果的空循环
- 遍历集合并删除元素时，必须使用 `Iterator.remove()`；需要新增或按索引修改时，使用普通 `for` 循环或其他安全方式

### HA-D008 [强制] switch 分支必须显式终止并覆盖默认场景

每个非空 `switch` 分支必须以 `break`、`continue`、`return`、`throw` 等方式显式终止；禁止无说明的 case 贯穿。`switch` 必须包含 `default` 分支，并对未匹配场景进行明确处理。

**说明**：
- 如确有意图使用 case 贯穿，必须通过清晰注释说明，并确保贯穿逻辑正确
- `default` 分支应按业务需要执行兜底、记录日志或抛出异常；即使无需处理，也应保留空 `default` 表明已评估未匹配场景

### HA-D009 [强制] 禁止使用存在性能或线程安全风险的工具类

禁止使用 apache 包的 `ProcessInfoUtil`，特别是不得调用存在 CPU 风险的 `getHostNameInfoByIp`；禁止使用 `SimpleDateFormat`，日期格式化必须使用 `DateTimeFormatter`。

### HA-D010 [强制] equals 调用与重写必须安全

调用 `equals` 时，常量必须置于左侧、变量置于右侧，避免变量为 `null` 时触发空指针异常。重写 `equals` 时必须同时重写 `hashCode`，确保逻辑相等的对象具有相同的哈希值。

**说明**：成对重写 `equals`/`hashCode` 的完整规范（何时重写、Set/Map 键要求）详见 `JAVA-03` N001，此处不重复定义；本条保留高可用增量：常量左置以防 `null` 触发 NPE。

### HA-D011 [强制] 浮点类型必须使用安全方式比较

禁止使用 `==` 或 `equals` 比较 `float`、`double`、`Float`、`Double` 或 `BigDecimal`；忽略 `BigDecimal` 精度时必须使用 `compareTo()`，其他浮点比较必须指定误差范围阈值 `epsilon`，并使用 `Math.abs()` 比较差值绝对值。

**说明**：浮点数与 `BigDecimal` 比较的完整规范（包装类型 `==` 禁用、`BigDecimal` 构造方式等）详见 `JAVA-02` N005；本条从高可用视角强调：错误的浮点比较会导致金额、库存等关键计算偏差。

## 三、示例

以下示例仅用于说明规则边界与意图，不代表唯一实现方式；实际生成或审查代码时，应优先复用项目现有框架、工具类、SDK 与命名，并以是否满足规则约束为判断标准。

### HA-D001 参数前置校验示例

#### good case:

```java
public OrderResult createOrder(OrderRequest request) {
    Preconditions.checkNotNull(request, "request must not be null");
    Preconditions.checkArgument(request.getAmount() > 0, "amount must be positive");
    Preconditions.checkArgument(request.getAmount() <= 999999,
        "amount exceeds limit: %s", request.getAmount());
    // 业务逻辑...
}
```

#### bad case:

```java
public OrderResult createOrder(OrderRequest request) {
    // 不校验直接使用，下游可能 NPE 或产生脏数据
    return orderMapper.insert(request.toEntity());
}
```

### HA-D007 循环与分支控制示例

#### good case:

```java
public void removeInvalidOrders(List<Order> orders) {
    if (orders == null || orders.isEmpty()) {
        return;
    }
    Iterator<Order> iterator = orders.iterator();
    while (iterator.hasNext()) {
        if (iterator.next().isInvalid()) {
            iterator.remove();
        }
    }
}

switch (status) {
    case PENDING:
        handlePending();
        break;
    case COMPLETED:
        handleCompleted();
        return;
    default:
        throw new IllegalArgumentException("unknown status: " + status);
}
```

#### bad case:

```java
while (true) { // 无明确退出条件
    poll();
}

for (int i = 0; i <= orders.size(); i++) { // i == size() 时越界
    process(orders.get(i));
}

for (Order order : orders) {
    if (order.isInvalid()) {
        orders.remove(order); // 抛出 ConcurrentModificationException
    }
}

switch (status) {
    case PENDING:
        handlePending(); // 忘记 break，意外贯穿
    case COMPLETED:
        handleCompleted();
}
```

### HA-D002 空指针防护示例

#### good case:

```java
UserInfo userInfo = userService.getUser(userId);
if (userInfo == null) {
    return Result.notFound();
}
String city = Optional.ofNullable(userInfo)
    .map(UserInfo::getAddress)
    .map(Address::getCity)
    .orElse(null);

Integer retryCount = configService.getRetryCount();
if (retryCount != null && retryCount > 0) {
    retry(retryCount);
}
```

#### bad case:

```java
UserInfo userInfo = userService.getUser(userId);
String city = userInfo.getAddress().getCity(); // Thrift 返回值和级联调用均未判空

Integer retryCount = configService.getRetryCount();
retry(retryCount); // 自动拆箱，retryCount 为 null 时抛出 NPE
```

### HA-D003 异常分类处理示例

#### good case:

```java
@ControllerAdvice
public class GlobalExceptionHandler {

    @ExceptionHandler(BizException.class)
    public Result<?> handleBiz(BizException e) {
        log.warn("biz error: code={}, msg={}", e.getCode(), e.getMessage());
        return Result.fail(e.getCode(), e.getMessage()); // 不触发告警
    }

    @ExceptionHandler(SystemException.class)
    public Result<?> handleSystem(SystemException e) {
        log.error("system error", e); // 完整堆栈
        Cat.logError(e);              // 触发 Raptor 告警
        return Result.fail(ErrorCode.SYSTEM_ERROR, "系统繁忙，请稍后再试");
    }
}
```

#### bad case:

```java
// 业务异常和系统异常混为一谈
@ExceptionHandler(Exception.class)
public Result<?> handleAll(Exception e) {
    log.error("error", e); // 业务异常也触发 ERROR 告警，导致告警风暴
    return Result.fail("系统错误");
}
```

## 四、规范执行要点

- ✗ 禁止未判空使用 Thrift、RDS、Cellar、Squirrel 返回对象或 Mafka 消费对象
- ✗ 禁止未判空的级联调用
- ✗ 禁止将包装类型未判空即自动拆箱为基本类型
- ✗ 不建议空 catch（`catch(Exception e) {}`）
- ✗ 不建议丢失异常链（`throw new XXX("msg")` 而非 `throw new XXX("msg", e)`）
- ✗ 不建议业务异常触发熔断计数
- ✗ 禁止使用 `while (true)`、`for (;;)`、空循环或可能越界的循环
- ✗ 禁止在增强型 for 遍历集合时直接结构性修改该集合
- ✗ 禁止 switch case 无说明贯穿或缺少 default 分支
