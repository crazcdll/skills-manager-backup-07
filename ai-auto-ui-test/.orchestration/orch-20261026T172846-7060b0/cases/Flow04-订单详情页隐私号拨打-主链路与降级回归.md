## 号码弹窗唤起路径（实测，三层）

> 2026-10-26 在订单 `{order_id}`（720×1280 云模拟器）实测：点「联系酒店」出现的只是**商家号浮层**，必须再点 2 层才能唤起隐私号呼出弹窗。

1. **L1** 订单详情页点「联系酒店」→ 底部浮层出现「咨询酒店 / 在线联系 / 电话联系 + 酒店电话…」
2. **L2** 点浮层里的「电话联系」行（`tap-text 电话联系`，坐标 ≈ (193,969)；兜底顺序：行容器 (360,953) → 右侧听筒图标 (581,953)）→ 出现**号码选择弹窗**（列出 `010-53913316` / `18519274883` / `取消`）
3. **L3** 在号码弹窗里点具体号码（第一个 ≈ (360,900)，第二个 ≈ (360,1015)）→ 出现**隐私号呼出弹窗**

关键约束（务必遵守）：

- **L2 号码选择弹窗、L3 隐私号呼出弹窗均不在原生视图树内**（`find-text` / `inspect-tree` 采不到节点）→ L3 之后一律用**坐标点击 + `kind=visual` 读图断言**，不要用 assert-text。
- 因此**本文件内所有「弹窗内文案」的文案断言，一律按视觉断言（读图）执行**。
- 关闭：隐私号弹窗「取消」≈ (223,659)；号码弹窗「取消」≈ (360,1128)；浮层用 back 关闭。
- `find-text` 需全串匹配（如 `咨询酒店` 查不到，须用全串 `咨询酒店（设施 早餐 入住退房时间等问题）`）；`tap-text` 有唯一子串兜底，不受影响。
- 若 L1 浮层里没有「电话联系」（如协商取消页形态不同），先 dump 元素树确认浮层结构，再按同样的「先选联系方式行、再选号码」思路推进，并在报告里注明实际路径。
- 「场景 D · IM 联系入口」不走本路径，按该场景自己的入口进入。

## 场景 A · 正常环境立即呼叫

### S1. 点击联系酒店唤起呼出弹窗

**操作**：按「号码弹窗唤起路径（实测，三层）」L1→L2→L3 唤起隐私号呼出弹窗：点「联系酒店」→ 点「电话联系」行 → 点具体号码。

**等待**：号码呼出弹窗展示。

**校验**：
- 「将使用该号码加密呼出」 — 渲染就绪标志
- 「双卡双待请确认，系统呼出号码和下方一致」 — 文案断言

### S2. 点击立即呼叫

**操作**：点击「立即呼叫」。

**等待**：系统拨号呼出（隐私号绑定呼出）。

**校验**：
- 呼叫正常发起（进入系统拨号界面） — 视觉确认

**接口断言**：`POST /hotelorder/v1/bindvirtualnumber.json`
- 绑定虚拟号成功后发起呼出

### A1. bindvirtualnumber 接口返回校验

- 接口 `POST https://apihotel.meituan.com/hotelorder/v1/bindvirtualnumber.json` 调用成功（error.code=200）
- 返回虚拟号码，呼叫链路正常发起

**证据要求**：截图或录屏记录呼叫发起（系统拨号界面）
