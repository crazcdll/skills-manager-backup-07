# 第六步：报告归档规范（标题 + 结构 + 存放位置）

本文件是评估报告**落到学城时的唯一真相源**，定义三件事：

1. **存放位置**：按月分目录，禁止再往归档根目录平铺
2. **标题规范**：全局统一格式，机器可解析
3. **内容结构**：固定章节骨架，跨仓库可横向对比

> 违反本规范产出的报告，会导致归档目录被打满、无法按月检索、跨报告无法对比。

---

## 一、存放位置：按月分目录

### 为什么必须分目录

学城对**单个父文档下的子文档数量**存在硬上限（实测 **500**）。超出后
`createDocument` 直接返回 `code=708`，**新报告完全无法保存**。

历史上所有报告平铺挂在归档根目录 `2756859002` 下，该目录已打满 500，
处于「一篇都写不进去」的状态。

### 目标结构

```
2756859002  AI-Ready-Repo 打分报告归档（ROOT，只放月度目录）
  ├── 【2026-05】AI-Ready-Repo 打分
  ├── 【2026-06】AI-Ready-Repo 打分
  ├── 【2026-06】AI-Ready-Repo 打分 · 卷2     ← 单月满 480 篇自动开卷
  └── 【2026-07】AI-Ready-Repo 打分
```

- ROOT 每年只新增 12~15 个子节点，永不触顶
- 单月目录写满 480 篇（留 20 篇安全垫）自动开「· 卷2」
- 月度目录**由脚本自动维护，禁止手工创建或改名**——手工命名对不上
  `MONTH_DIR_RE` 正则，脚本会认不出来并重复创建

### 如何获取当月目录 ID

**禁止硬编码 `--parentId`**，一律通过脚本解析（不存在则自动创建）：

```bash
PARENT_ID=$(python3 "$SKILL_ROOT/scripts/km_report_dir.py" resolve --quiet)
```

`resolve` 的行为：
- 当月目录已存在且未满 → 返回其 `contentId`
- 已存在但满了 → 自动创建下一卷并返回新卷 ID
- 不存在 → 创建后返回
- ROOT 已打满 → 报错并提示先跑 `migrate`

> stdout 只输出纯 `contentId`，人类可读日志走 stderr，可安全用于 `$(...)`。

## 二、标题规范

### 格式

> 前提（已实测）：**学城目录按标题字典序展示，不是按创建时间。**
> 所以“目录怎么排”完全由**标题开头的字段**决定。

支持两种排序形态，字段完全一致，只是「仓库名」与「日期」谁在前：

```
date 形态（默认）：<YYYY-MM-DD> | <仓库名> | AI-Ready 评估报告 | #N | <得分>分
repo 形态：        <仓库名> | AI-Ready 评估报告 | <YYYY-MM-DD> | #N | <得分>分
```

各段用 `|`（半角竖线，前后各一空格）分隔；`#N` 和分数段可选。

实例：

```
2026-07-31 | deal-shelf | AI-Ready 评估报告 | 78.5分        ← date 形态（默认）
2026-07-31 | deal-shelf | AI-Ready 评估报告 | #2 | 83分   ← 同仓库同日第 2 次评估
deal-shelf | AI-Ready 评估报告 | 2026-07-31 | 78.5分        ← repo 形态
```

### 选 repo 还是 date？

| | date 形态（默认） | repo 形态 |
|---|---|---|
| 目录排序效果 | 按日期聚合 | 按仓库名聚合 |
| 适合 | 看“**最近评了哪些**” | 看某个仓库的**分数趋势**（历次评估相邻） |
| 代价 | 同仓库多次评估被打散到不同位置 | 月内跨度最长 27 天，看不出新旧 |

默认选 **date** 的依据：评估频率高时，“最近评了哪些”比“某个仓库的分数趋势”
更常被关注——打开月度目录一眼就能看到今天/昨天评了什么，而**月度目录本身
已经承担了时间维度的归档**。若想看某仓库的历次分数趋势，用 `--order repo`
切过去即可（同一仓库复评占比约 28%~37%，切过去也不亏）。

两种形态**可混存于同一目录**，解析器两种都认，同日去重也能跨形态生效——
**切换时不需要改名历史文档**。

### 为什么分数必须在末尾

1. 排序主键始终是开头字段（日期或仓库名），**不被分数打乱**
2. 已归档的**无分数旧标题仍属合规**（分数段可选），无需回头改名历史文档
3. 同日去重只比对「仓库名 + 日期」，**不看分数、不看形态**
4. 解析器同时兼容旧格式（空格分隔）和新格式（`|` 分隔），切换时无需改名历史文档

### 字段规则

| 字段 | 规则 |
|------|------|
| `<仓库名>` | 仓库名**本体**，去掉 git URL 外壳与 org 前缀（`ssh://git@git.sankuai.com/tuangou/deal-shelf.git` → `deal-shelf`）；npm scope 包名整体保留（`@game/com-floating-window-seed`） |
| `AI-Ready 评估报告` | 固定文案，注意 `AI-Ready` 中的连字符、`评估报告`前后各一个半角空格 |
| `<YYYY-MM-DD>` | 评估当天日期，**必须半角连字符**，禁止 `2026/06/22` 这类斜杠写法 |
| `#N` | 仅同仓库同日重复评估时追加，从 `#2` 起；单独一段，用 `|` 与前文分隔 |
| `· <分数>分` | 综合得分（0–100），**最多保留一位小数且去掉尾零**（`78.0` → `78分`，`71.46` → `71.5分`）；间隔号 `·`（U+00B7）后接数字；**固定在标题末尾** |

### 禁止的写法

以下均为历史上真实出现过、导致无法机器解析的反例：

| 反例 | 问题 |
|------|------|
| `ai-ready-report-colombo-benefits.md` | 带文件名后缀，无仓库名/日期结构 |
| `cip-incentive-template | AI-Ready 评估报告 | 2026/06/22` | 日期用斜杠 |
| `deal-rank-list-plugins | AI-Ready 评估报告（第二次）| 2026-06-04` | 用括号标注次数而非 `#N`，且日期位置错乱 |
| `dzhealth-medical | AI-Ready 评估报告（第三次 71.33分）` | 缺日期；次数应用 `#3`，分数应写作 ` | 71.3分` |
| `AI-Ready 仓库评估报告（v2）— credit-case-web | 83.10分` | 仓库名位置错误；分数未用 ` | 83.1分` 格式 |
| `AI-Ready test-204` | 无意义标题 |

> **版本号与评估次数不进标题**（`（v2）`、`（第三次）`）——重复评估统一用 `| #N` 表达。
> 分数只能以 `| <分数>分` 的形式出现在**标题末尾**，写在其他位置会破坏排序与解析。

### 如何生成标题

同样禁止手拼，用脚本生成（自动格式化分数 + 处理同日去重）：

```bash
TITLE=$(python3 "$SKILL_ROOT/scripts/km_report_dir.py" title \
          --repo-name "$REPO_NAME" --score "$TOTAL_SCORE" --parent-id "$PARENT_ID")
# → 2026-07-31 | deal-shelf | AI-Ready 评估报告 | 78.5分
```

`--score` 传第三步算出的综合分（直接给原始值即可，脚本会帮你取一位小数并去尾零）；
超出 0–100 或非数字会直接报错，避免把脏数据写进标题。不传 `--score` 则退化为无分数标题。

**切换排序形态**（二选一，默认 `date`）：

```bash
# 单次指定
python3 "$SKILL_ROOT/scripts/km_report_dir.py" title --repo-name deal-shelf \
  --score 78.5 --order repo --parent-id "$PARENT_ID"
# → deal-shelf | AI-Ready 评估报告 | 2026-07-31 | 78.5分

# 团队级默认（写进 shell profile 即可全局生效）
export AI_READY_TITLE_ORDER=repo
```

切换后**无需回头改名已有文档**：两种形态可混存，`audit` 与同日去重均能跨形态识别。
但同一个团队建议固定一种，否则目录里会出现两簇各自排序的标题。

### 结构硬约束

1. **六个一级章节固定**：概要 / 总览 / 详情 / 总结 / 路线图 / 附录，不得增删改名
2. **元信息表在最前**：综合分、评级、仓库形态、仓库类型和权重档案必须出现在「一、评估概要」表格中
3. **mono-repo 成员完整**：2.1 必须覆盖构建清单中的全部成员，父仓综合分等于全部成员综合分的算术平均值
4. **维度顺序固定**：始终按 dim1a → dim1b → dim2 → … → dim10（即 L1→L6）排列；mono-repo 在每个成员内分别保持此顺序
5. **加权分必须展示**：单仓 2.2 每行加权分 = 原始分 × 权重，合计须等于综合分；mono-repo 的父仓维度均值不得伪装成加权分
6. **标题分数与正文一致**：标题末尾的 ` · <分数>分` 必须等于「一、评估概要」表中的综合得分（四舍五入到一位小数）
7. **改进建议必须可执行**：附预计投入与预期提分，与 SKILL.md 第四/五步一致

## 四、历史数据治理

归档根目录下遗留的 500 篇平铺文档，用 `migrate` 一次性归位：

```bash
# 1. 先盘点（只读）
python3 "$SKILL_ROOT/scripts/km_report_dir.py" audit

# 2. 预演迁移计划（dry-run，不落任何改动）
python3 "$SKILL_ROOT/scripts/km_report_dir.py" migrate

# 3. 确认无误后执行
python3 "$SKILL_ROOT/scripts/km_report_dir.py" migrate --execute
```

- 迁移按**文档创建时间**归入对应月份目录，不改标题、不改内容
- 单月超 480 篇自动开卷
- 若根目录混有非 AI-Ready 报告（如 PRD、技术方案），加 `--only-reports`
  仅迁移标题含 `AI-Ready` 的文档，其余留在原处由人工处置

**根目录已打满时如何破局**：根目录满 500 时连月度目录都建不出来，形成
「满 → 建不了目录 → 没法迁移 → 一直满」的死锁。`migrate` 通过**引导式建目录**
自动化解：先把月度目录建在个人空间根（detached），迁走文档腾出空位后，
再 `moveDocument` 把目录挂回根目录。全过程无需人工介入。

**可安全重跑**：
- 中途失败遗留在个人空间的月度目录，下次执行会被自动识别并复用（`♻️` 标记），
  不会重复创建同名目录
- SSO token 抖动、网络超时等瞬时故障自动退避重试（3s → 6s）；
  非瞬时故障（如无权限）立即报错，不浪费重试

> ⚠️ `migrate --execute` 会调用 `moveDocument` 批量移动文档，属于写操作。
> **执行前必须先看 dry-run 输出并获得用户确认**，禁止静默执行。

> 💡 若 citadel 报 `token_exchange_command 执行超时`，说明本地 SSO 凭证已过期，
> 执行 `oa-skills citadel <任意命令> --force-ciba` 走大象确认重新授权即可。
