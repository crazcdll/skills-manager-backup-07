# flex-design 视觉设计生成规则

## 前置：踩坑文档

> **MUST**：在生成 flex-design 内容前，先通过 citadel skill 执行 `oa-skills citadel getMarkdown --contentId 2749764228` 读取踩坑文档，了解常见踩坑与反例约束，在生成所有内容时必须遵循该文档中的规则。

## 规则要求（IMPORTANT）

### 结构布局分析规则
1. 视觉稿的整体布局结构不能单纯依赖数据读取，需要结合视觉稿数据结构与物料图片分析结果进行最终位置确认，保证物料位置和层级的准确性。

### 视觉样式分析规则
1. 当视觉稿中声明 display: flex; flex-direction: row; align-items: center; 但未声明 justify-content 时，默认使用 justify-content: flex-start。
2. 设计稿尺寸需缩放一半：如设计稿 100px 对应代码 50px。在生成 flex-design 文档的时候，写入计算后的值。
3. 视觉稿中的 gap 属性在 Max 技术栈中不允许使用，视觉分析结果数据中需要将 gap 转换为 margin 或 padding。
4. 如果父元素声明了 flex 布局并且设置了 gap 属性，需要使用 margin 将 gap 属性的数组转换为子元素之间的间距，确保元素之间的间距是正确的。

## 整体框架必填字段及融合逻辑

| 字段 | 融合逻辑 |
|------|---------|
| **描述** | 综合 DSL 根节点的布局方向 + 图片分析的分区结果，一句话概括整体布局 |
| **骨架 ASCII** | 以图片分析识别的模块层级为骨架，用 DSL 节点树验证和修正层级关系 |
| **间距** | 从 DSL 提取 padding/margin 精确值；DSL 缺失时以图片分析估算值补充，标注 `[图片估算]` |
| **排版** | 从 DSL 提取字号/字重/颜色/行高；图片分析补充对齐方式 |
| **颜色** | 从 DSL 提取各节点 background/color 色值，归类整理为色板 |
| **CSS** | 从 DSL 提取所有样式属性，结合踩坑文档校验合规性，输出完整样式块 |
| **Mock 数据** | 从 DSL 提取文本/图片/数值内容，结合 Spec 业务字段补充语义化字段名 |

## 子模块必填字段及融合逻辑

**每个子模块（含所有层级嵌套子模块）** 必须逐项补全以下字段：

| 字段 | 融合逻辑 |
|------|---------|
| **描述** | 结合 DSL 节点类型 + 图片分析该区域的视觉角色 + Spec 业务含义 |
| **框架** | 以图片分析的子区域划分为基础，用 DSL 节点的 flex-direction/子节点数验证，输出 ASCII 骨架并标注 flex 方向 |
| **间距** | 从 DSL 提取该节点的 padding/margin/gap；DSL 缺失时以图片像素间距估算，标注来源 |
| **排版** | 从 DSL 提取 fontSize/fontWeight/color/lineHeight；对齐方式优先取 DSL，图片分析补充 |
| **颜色** | 从 DSL 提取该模块特有色值；若与整体框架一致则注明"继承整体框架" |
| **CSS** | 从 DSL 提取该节点完整样式，结合踩坑文档校验。**flex/flex-shrink/align-items/justify-content 必须从 DSL 读取，不可凭空猜测** |
| **Props** | 根据组件检索结果中匹配组件的 API 文档，列出参数（参数名、类型、默认值、说明）；将 DSL 数据映射到对应 Props |
| **推荐组件** | 从组件检索结果取匹配的 Max/Leez 组件名，附简要使用说明 |
| **图标处理** | 优先从 Max/Leez 图标库检索（如 `leez-icon`）；无匹配时才用视觉稿图片资源 |
| **Mock 数据** | 从 DSL 提取该模块文本/图片/数值，以 Spec 字段名为 key 输出 JSON |
| **交互状态** | 从 Spec 提取交互要求（按压/禁用/加载），结合组件文档的状态支持，填写各状态视觉变化与过渡；Spec 未提及的状态填「—」 |
| **边界情况** | 结合 DSL 尺寸约束（min/max-width/height）+ Spec 异常场景描述，填写文字过长、空状态、最小/最大尺寸的处理方式 |

## 冲突解决与补充规则

- **DSL 与图片冲突时**：以 DSL 精确数值为准，图片分析仅作辅助验证
- **额外视觉特征**：若存在渐变、动画、图层叠加、滚动行为等，须自行补充，不局限于上述字段列表
- **嵌套要求**：每个子模块及其所有层级的嵌套子模块（如 B-1、B-1-a、B-2-b 等）都须逐项补全，**不可只写名称或骨架占位**
- **组件统计**：末尾输出总模块数、Max 组件数、Leez 组件数

## 输出模板

> **MUST**：最终输出必须严格遵守 [assets/flex-design-template.md](../assets/flex-design-template.md) 的结构与格式，包括：章节顺序、标题层级、表格表头与列顺序、字段命名、代码块语言标识、占位符位置。不得新增、删除、合并或重排模板中的任何章节/字段；模板未覆盖的额外内容只能作为补充追加到对应章节末尾，且不得破坏既有结构。

### 强制执行顺序

1. **第 1 步：读模板**。写任何内容前，必须先完整读取 [assets/flex-design-template.md](../assets/flex-design-template.md)，把模板视为"填空题骨架"。
2. **第 2 步：复制骨架**。以模板原文为基础，**保留全部一级/二级/三级章节标题和顺序**，只替换占位符 `[...]` 和示例内容，不得自行改写章节名。
3. **第 3 步：逐模块填充**。按整体框架中列出的 A / B / C... 顺序，在 `## 3 子模块详细数据` 下逐个展开，每个子模块（含嵌套）**必须完整出现以下 10 个字段**，顺序不可乱：`描述` → `框架` → `间距` → `排版` → `CSS` → `Props` → `推荐组件` → `Mock 数据` → `交互状态` → `边界情况`。
4. **第 4 步：写入学城文档前自检**：
   4.1 根据下方校验清单中的规则对当前编写的 flex-design 文档进行检查，内容完全符合规则后，才可以写入学城。
   4.2 逐条对照本文件「规则要求」中的视觉样式分析规则，对当前编写的 flex-design 文档逐条检查（重点：尺寸已 ÷2、无 gap 属性、flex-direction/justify-content 已从 DSL 读取），内容完全符合规则后，才可以写入学城。

### 必须保留的章节白名单

最终文档**有且仅有**以下一级章节，顺序不可改：

| 序号 | 一级章节 | 必需子章节 |
|------|---------|-----------|
| 1 | `## 1 视觉稿图片` | 嵌入视觉稿图片 |
| 2 | `## 2 整体框架` | `描述` / `骨架` / `间距` / `排版` / `颜色` / `CSS` / `Mock 数据` 七个加粗小节 |
| 3 | `## 3 子模块详细数据` | 每个子模块及其所有嵌套层级，均包含上述 10 个加粗字段 |
| 4 | `## 4 组件统计` | 总模块数 / Max 组件数 / Leez 组件数 |

**禁止**自造以下小节并放到上述结构之外（若确有必要，只能追加到最对应的一级章节**末尾**，不得替代必需字段）：
- `视觉稿概览` / `设计 tokens` / `图片资源` / `组件映射` / `交互动效` / `Stage 规划` / `无障碍与适配` / `附：CSS 原文` 等自由命名章节。
- 设计 tokens、图片资源等信息应分别落到"整体框架 → 颜色/排版/CSS"、各子模块的"Mock 数据/CSS"中。

### 校验清单（Self-Check）

在调用学城写入接口之前，逐条核对（任意一条不通过则继续修正，不得写入）：

- [ ] 一级章节完全等于白名单中的 4 个，且顺序为 1 → 2 → 3 → 4。
- [ ] `## 2 整体框架` 下 7 个加粗小节齐全：`描述`、`骨架`、`间距`、`排版`、`颜色`、`CSS`、`Mock 数据`。
- [ ] `## 3 子模块详细数据` 覆盖整体骨架中列出的**所有** A / B / C... 以及它们所有层级的嵌套子模块，无遗漏。
- [ ] 每个子模块（含嵌套）都包含 10 个加粗字段，**字段名与顺序**与模板一致，没有只写名称或骨架占位的模块。
- [ ] 所有 CSS 代码块使用 ` ```css ` 语言标识；所有 Mock 数据代码块使用 ` ```json `；所有骨架 ASCII 使用无语言标识的 ``` 纯代码块。
- [ ] `## 4 组件统计` 末尾出现并填入数字。
- [ ] 未出现模板之外的自造一级/二级章节（见上方禁止清单）。
- [ ] 输出的 flex-design 文档中的尺寸数据为视觉稿值的一半。
- [ ] 输出的 flex 布局结构是结合视觉稿数据结构与物料图片分析结果进行最终位置确认，保证物料位置和层级的准确性。
- [ ] 保留视觉稿中所有元素之间的间距，不要有任何遗漏。
- [ ] 输出的视觉稿分析结果中不要有任何 gap 属性标记（包括整体框架、所有层级的子模块与嵌套子模块）。

任意一条不通过，先在本地内容中修正到完全符合后再写入学城。
