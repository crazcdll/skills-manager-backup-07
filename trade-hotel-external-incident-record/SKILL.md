# 酒店外部工单群聊转学城复盘文档

把一个因 TT 工单/客诉自动拉起的飞象排查群，完整梳理为一篇结构化的学城复盘文档，包含全部文字对话的时间线，并为图片、视频等媒体内容标注插入位置。

## 适用场景

- 大象机器人因 TT 工单自动拉群排查问题（典型标志：群内出现"您好：您可以直接在此群里沟通您的问题，TT链接：..."的机器人消息，以及"TT 长时间未操作提醒"/"当前工单已连续 48 小时无群内消息，已自动关闭"）
- 用户提供群号（纯数字 gid）和一个学城文档链接（可能已存在模板，也可能是空文档）
- 目标是把群里的排查过程沉淀为可长期归档、可检索的问题复盘文档

## 核心原则

1. **文字内容必须完整，不能有遗漏**：群聊消息分页/关键词检索可能出现跳跃或遗漏，必须做交叉验证（见 Step 2），不能只做一轮 offset 翻页就认为抓全了。
2. **图片/视频不能直接用 IM 外链写入学城**：飞象 IM 图片/视频托管在 `file.neixin.cn` 等域名，需要 IM 客户端会话级鉴权；学城 CDN 无法访问该域名，`citadel` CLI/`curl` 直连会返回 401，即使勉强把外链写进 XML，学城服务端也会在 `updateDocumentByXml` 时校验拦截，报错"禁止直接将外部资源写入学城文档"。**这不是权限问题，是两个系统鉴权域不同，必须走"用户手动从飞象客户端另存到本地 → `uploadImageToDocument`/`uploadVideoToDocument` 上传到目标学城文档"这条路径**，此 skill 不应尝试绕过（不得使用他人或当前用户的会话 cookie 冒用鉴权）。
3. **媒体位置必须醒目标注，不能默默丢弃**：抓取消息时识别出的每一处图片/视频，无论用户是否已上传，都要在文档对应位置插入一行加粗、**红色字体**的提示，明确"这里应该放哪张图/哪段视频、谁发的、什么时间、什么内容"，避免用户后续贴图时找不到位置或漏贴。
4. **群内沟通过程回顾要保留时间线颗粒度**，不要只写结论。要按时间顺序逐条列出关键发言人、发言内容、@提及关系，让读者能复现整个排查思路，而不仅仅是最终结论。

## 工具依赖

- `im_query_messages`：抓取群聊消息（文字、图片、视频、卡片、系统消息）
- `image_read`：仅用于让模型"看懂"图片内容辅助判断，**不能**用它把图片字节流导出为本地文件（当前工具边界不支持）
- `oa-skills citadel`（学城 CLI）：`getDocumentXml` / `updateDocumentByXml` / `uploadImageToDocument` / `uploadVideoToDocument` / `getSimpleMarkdown`

## 工作流程

### Step 0：确认输入

从用户消息中提取：
- 群号 `gid`（纯数字，`sessionType=groupchat`）
- 学城文档链接 → 提取 `contentId`（`km.sankuai.com/collabpage/<id>` 或 `/page/<id>`）

若文档已有内容（比如已有模板结构：问题描述/问题影响/原因/发现方式/总结&TODO），先用 `getSimpleMarkdown` 或 `getDocumentXml` 读取现状，复用已有结构；若是空文档，按 Step 4 的默认结构创建。

### Step 1：确定搜索时间范围，抓取群聊消息（按时间不遗漏）

**先判断用户是否明确指定了起始时间**，分两种情况处理：

- **情况 A：用户未指明时间，或明确要求"搜索这个群所有的聊天记录"** → 搜索范围不设起点，必须一直查到该群聊**最早的一条消息**（通常是建群消息/大象机器人首条 TT 通知），不能只翻几页就停。
- **情况 B：用户明确指定了一个开始时间**（如"从8月7日下午开始""从XX时间点往后"）→ 搜索范围从这个指定的开始时间起，**往后（朝当前时间方向）** 搜索到最新消息，不需要再往更早的时间翻页查找。此时不适用下面"定位建群时刻"的要求，只需确认从指定起始时间到最新消息之间没有遗漏即可。

抓取与验证方法：

1. 先用 `im_query_messages`（不带 query，`limit`+`offset` 分页）翻页抓取；情况 A 从最新往前翻到 `hasMore:false` 为止（即翻到群聊最早消息），情况 B 只需覆盖"指定开始时间"到"当前最新消息"这个区间。
2. **交叉验证，防止遗漏**：仅靠 offset 分页在部分群可能出现跳跃或重复窗口（同一时间段被返回多次，而更早或某段时间的窗口被跳过）。必须额外用以下方式做交叉核对：
   - **情况 A**：搜索关键词 `"TT链接"` / TT 工单 ID，定位建群时刻（通常是群聊最早的消息），确认这就是搜索范围的起点；搜索关键词 `"已自动关闭"` / `"长时间未操作"`，定位群聊结束时刻。对比"建群时刻"和"offset 翻页拿到的最早消息时间"，如果两者之间还有时间空隙（例如相差几小时），必须针对这段空隙用关键人名、关键操作词（如"录屏""截图""订单""注册"等）做二次关键词检索，把空隙里的消息找全。
   - **情况 B**：以用户指定的开始时间为起点，对比"该起点"和"offset 翻页拿到的最早消息时间"，如果翻页结果比指定起始时间更晚（说明中间有空隙未覆盖），同样需要用关键人名、关键操作词做二次检索补齐，直至覆盖到指定起始时间为止；不需要再往指定起始时间更早的方向查找。
   - 无论哪种情况，对每条被引用（`kind:"quote"`）但引用目标不在已抓取列表里的消息，都要用 `messageId` 精确回查该引用消息本身。
3. **识别媒体消息**：
   - 图片消息：`kind` 为 `image` 或 `rich-text`（正文含 `[图片]` 且带 `imageReadUrl`），记录发送人、时间、`imageReadUrl`、图片描述（如有正文说明）
   - 视频消息：`kind` 为 `video` 或引用/正文含 `[视频]`，记录发送人、时间、`imageReadUrl`（视频首帧缩略图）。**视频消息的 `text` 字段通常为空**，不能仅靠关键词"视频"搜索，需结合上下文（如某人说"我发个录屏/视频到群里"后紧跟的下一条消息）定位
   - 系统消息（入群/退群/撤回）按需保留，通常只需摘要一句，不用逐条展开

### Step 2：整理时间线要素

对全部消息，按时间顺序整理出：
- 问题触发：TT 工单号、用户ID、POI/门店、问题现象（通常来自大象机器人的建群消息）
- 排查过程：谁在什么时间说了什么、@了谁、下了什么结论、贴了什么证据（日志/trace/代码截图/录屏）
- 关键结论：根因定位、责任人、后续 TODO
- 收尾：工单是否自动关闭、群内最后状态

### Step 3：处理图片/视频

对 Step 1 识别出的每一处媒体：

1. **先检查文档里是否已经有对应的学城 CDN 图片/视频节点**（`<img src="https://km.sankuai.com/api/file/cdn/...">` 或 `<km-attachment src="https://km.sankuai.com/api/file/cdn/...">`），如果用户已经手动贴过，保留原节点，只在其前面补一行 `👉【已插入图片/视频】<发送人 时间 内容说明>` 的加粗**红色**提示（`<p><strong><span style="color:#FF0000">👉【已插入图片/视频】...</span></strong></p>`）。
2. **如果媒体尚未上传到学城**，不要尝试用 IM 原始 URL（`file.neixin.cn` 等）直接写入 `<img src="...">` 或 `<km-attachment src="...">`——会被学城服务端拦截报错。正确做法：
   - 在该媒体应出现的位置插入一行加粗**红色**提示：`<p><strong><span style="color:#FF0000">👉【此处插入截图/视频】<发送人> <日期 时间> 发送的<内容描述></span></strong></p>`
   - 同时告知用户：该图片/视频尚未能自动上传，需要用户从飞象客户端把它另存到本地，把路径发给我后，用 `uploadImageToDocument --contentId <id> --image <本地路径>` 或 `uploadVideoToDocument --contentId <id> --file <本地路径>` 上传并替换掉提示行
3. **不要尝试**：
   - 用 `curl`/`uploadImageToDocument --imageUrl` 直接拉取 `file.neixin.cn` 等 IM 域名的图片（会 401）
   - 用任何方式获取或复用大象客户端的登录态/cookie 去绕过鉴权（红线，禁止）
   - 把学城拒绝写入的外链图片"硬写"进文档蒙混过关

### Step 4：写入学城文档

默认结构（若文档已有模板则沿用原结构和已有 nodeId，只补充空白段落，不破坏已有节点）：

```
【问题描述】—— 用户/门店/现象一句话概述，紧跟对应的截图/视频插入提示或已有节点
【问题影响】—— 谁受影响、影响面
【原因】—— 根因结论 + 关键证据（trace、代码逻辑、接口返回等），逐条列出，附对应截图提示或已有节点
【发现方式】—— 如何发现该问题（TT工单/客诉/巡检等）+ TT 链接
【群内沟通过程回顾】—— 按时间顺序列出关键发言，格式：`YYYY-MM-DD HH:mm 发言人：内容摘要`，媒体消息处插入👉红色标记
【总结&TODO】—— 结论 + 待办事项（负责人、内容），已关闭的工单注明关闭方式
```

写入方式：

```bash
# 先获取当前 XML 和 stepVersion
oa-skills citadel getDocumentXml --contentId <docId> --output /tmp/doc.xml

# AI 在本地编辑 /tmp/doc.xml：
# - 保留 <km-doc>/<km-title> 及已有 nodeId
# - 在已有段落标题下补充正文 <p> 节点
# - 媒体位置插入红色提示行 <p><strong><span style="color:#FF0000">👉【...】...</span></strong></p>
# - 已有学城 CDN 图片/视频节点原样保留，不改动 src

oa-skills citadel updateDocumentByXml --contentId <docId> --file /tmp/doc.xml --step-version <stepVersion>
```

**XML 合规要求**（继承学城 skill 通用约束）：
- 根标签仅 `<km-doc>`，`<km-title>` 唯一且为首个子节点
- 不使用 `<div>`/`<section>`/`<thead>`/`<tbody>` 等布局标签
- 已有节点的 `nodeId` 保留，新增节点可省略 `nodeId`
- 图片/视频节点的 `src` 只能是 `https://km.sankuai.com/api/file/cdn/...` 格式，绝不写入外部域名
- 媒体插入提示行统一使用红色字体：`<p><strong><span style="color:#FF0000">👉【...】...</span></strong></p>`，不要使用默认黑色

### Step 5：完成后向用户汇报

必须清晰说明三件事：
1. 文字内容整理进度（时间线覆盖范围：从建群到工单关闭/最后一条消息）
2. 已成功上传/保留的图片、视频清单
3. 仍需用户手动处理的媒体清单（逐条列出：发送人、时间、内容描述、文档中标记的提示位置），并给出下一步（另存到本地→发路径给我）

## 反遗漏检查清单（写入文档前必须逐项确认）

1. ✅ 已按 Step 1 的判断结果确定正确的搜索范围：未指定时间/要求"全部记录"时已定位到群聊最早消息（建群/TT机器人首条消息）；指定了开始时间时已确认覆盖该时间点到最新消息，且未误做超出范围的更早翻查
2. ✅ 确定的搜索范围（起点到终点）时间跨度内没有未检查的空隙，对空隙时间段做过至少一轮关键词补充检索（人名、动作词如"录屏""截图""看下""订单"等）
3. ✅ 所有 `kind:"quote"` 消息引用的原始消息都已找到或确认为已抓取范围内
4. ✅ 所有图片、视频消息都已识别并在文档中有对应位置（已插入或已标注提示）
5. ✅ 没有把任何非学城 CDN 域名的 URL 写入 `<img src>` 或 `<km-attachment src>`
6. ✅ 已有的学城 CDN 图片/视频节点未被误删或误改 `src`
7. ✅ 时间线中每条关键消息都保留了发言人和大致时间，而不是笼统概括
8. ✅ `updateDocumentByXml` 成功返回，`stepVersion` 未冲突（若冲突需重新 getDocumentXml 后重试）

## 边界

- 不主动创建学城文档；文档链接必须由用户提供
- 不删除、不覆盖用户已经手动上传的图片/视频节点
- 不尝试任何形式的鉴权绕过来获取 IM 媒体文件
- 不在未与用户确认的情况下大幅改写已有文档结构（如有既定模板，优先复用）

## 示例

**输入**：群号 70893088156，把这个群里面的内容整理到这个学城文档 https://km.sankuai.com/collabpage/2779702706，要加上所有的图片和视频

**执行流程**：
1. Step 0：提取 gid=70893088156，contentId=2779702706；读取文档发现已有【问题描述】【问题影响】【原因】【发现方式】【总结&TODO】模板骨架和一个 TT 链接
2. Step 1：offset 分页抓到 51 条消息（18:03 起），关键词检索 "TT" 定位到建群消息在 11:24，发现 11:24~18:03 之间有空隙；对空隙做人名/动作词检索，补齐 16:33~18:03 的 8 条消息 + 1 条视频（16:38 仲欣发的录屏，通过"我发个录屏到群里"+"操作时间就是16:38"+17:17被引用三处交叉定位）
3. Step 2：整理出问题触发（TT 339748308）、根因（5年前提单页会员组件被注释）、责任人和 TODO
4. Step 3：识别出 3 张截图 + 1 段视频；用户后续手动上传了 1 段视频 + 3 张截图到文档，为其中 2 张截图补加"👉【此处插入截图】"提示（用户尚未上传），为已上传的媒体补加"👉【已插入视频/截图】"说明
5. Step 4：按结构写入【群内沟通过程回顾】完整时间线，`updateDocumentByXml` 两次迭代完成（一次补文字时间线，一次加媒体位置标记）
6. Step 5：向用户说明文字已完整覆盖全流程，哪些图已上传、哪2张图仍需用户另存后发路径
