## HA-10 接口兼容性规范（审查精要）

| 编号 | 规则 | 级别 |
|------|------|------|
| MT:HA-API001 | 字段变更必须向后兼容：禁止删除/改类型，新增必须optional有默认值，枚举消费必须有default | P0（需满足下方前置条件） |
| MT:HA-API002 | 序列化安全：Jackson FAIL_ON_UNKNOWN_PROPERTIES=false，Thrift字段标optional，Protobuf用reserved | P1 |
| MT:HA-API003 | 接口版本管理：新旧共存 ≥2个迭代周期，按调用方灰度切流，禁止一次性全量切换 | P1 |

### MT:HA-API001 P0 判定前置条件（必须全部满足）

1. **变更载体必须是跨部署单元契约**，命中以下任一：
   - Thrift IDL 文件（`*.thrift`）
   - 对外接口定义（`*Service` / `*Facade` 等 interface 声明，**非 `*Impl`**）
   - 二方库对外暴露的 public API
   - 跨服务传输的序列化 DTO
2. **必须附带调用方反查证据**：给出至少一个外部调用点的「文件路径 + 行号」。**无证据不得判 P0。**

### MT:HA-API001 降级规则

- `*ServiceImpl` / `*Impl` 实现类的**内部方法签名变更** → **最高 P2**（重构规范建议）。理由：同编译单元内调用方编译期即报错，`mvn compile` 直接失败，无法逃逸至线上。
- 仅在**同仓库内被调用**、未对外暴露的 public 方法签名变更 → **最高 P2**。
- **无法确认调用方范围** → **降为 P2**，并在结论中标注「需人工确认是否存在外部调用方」。
- **禁止**以「是否已通知所有调用方」「建议确认是否存在外部调用」这类**疑问/假设句式**作为 P0 定级依据；此类表述本身即表明证据链不完整，必须降级。

| 变更场景 | 级别 | 依据 |
|---|---|---|
| Thrift IDL 删除字段 / 改字段类型 | P0 | 跨部署单元契约破坏，调用方运行时失败 |
| 二方库 `XxxFacadeService` interface 签名变更，且已反查到外部调用点（含文件+行号） | P0 | 载体命中 + 证据完整 |
| `XxxServiceImpl` 内部方法参数合并（同仓库重构） | P2 | 编译期可拦截，无法逃逸线上 |
| 接口签名变更但未反查调用方 / 无法确认调用范围 | P2 | 证据不足，禁止判 P0，需标注人工确认 |

### 字段变更正确流程
1. 旧字段标记 `@Deprecated`，通知调用方迁移
2. 新增字段（optional + 默认值）替代
3. 双写过渡（同时写旧字段和新字段）
4. 确认无调用方使用旧字段后删除（至少保留2个迭代周期）

### 强制禁止
- ✗ 禁止直接删除已有字段
- ✗ 禁止直接修改字段类型
- ✗ 禁止 FAIL_ON_UNKNOWN_PROPERTIES 为 true
- ✗ 禁止 Thrift 字段不标 optional
- ✗ 禁止复用已删除字段的 ID/编号
- ✗ 禁止直接暴露领域模型作为接口响应
- ✗ 禁止不兼容变更一次性全量切换

### 检查点
- [ ] 接口变更是否向后兼容
- [ ] 删除字段是否走了 @Deprecated 流程
- [ ] 新增字段是否 optional 且有默认值
- [ ] 枚举消费是否有 default 分支
- [ ] Jackson 是否配置了 FAIL_ON_UNKNOWN_PROPERTIES=false
- [ ] 接口响应是否使用独立 DTO
