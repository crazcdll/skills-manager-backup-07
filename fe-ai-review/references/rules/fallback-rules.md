# Fallback 审查规则

仅在 `mt-code-standards-setup` Runner 同步失败时读取本文件；同步成功时不使用本文件。

本文件只覆盖静态工具和常规 Agent 容易漏掉、且能从本次变更中取得具体证据的问题。技术栈或容器特有约束仍以平台 L1/L2/L3 规则为准，不在此复制。

- `source_type`：`fallback`
- `scope_level`：`FALLBACK`
- `rule_set_id`：`fe-ai-review-fallback`
- `rule_version`：`v2`
- `file`：`rules/fallback-rules.md`
- `title`：`Fallback 审查规则`
- `section`：命中规则的二级标题

命中时至少给出一项变更代码证据和对应风险；不要把未证明的缺失实现、纯风格问题或专项技术栈猜测作为发现项。

## FB01：对外契约与影响面

导出函数、组件、类型、参数、默认值、枚举或接口字段变化时，检查调用方、上下游和迁移兼容性。

关注新增必填字段、删除或改名、参数顺序或类型收窄、默认行为变化、后端字段和枚举不一致。

## FB02：外部输入、空值与异常路径

接口响应、路由或 Query、存储、JSON 解析和类型转换应区分缺失、非法和合法 falsy 值，并处理网络或业务异常、空数据和非预期数据结构。

重点检查 `value || default` 误覆盖 `0`、`''`、`false`，未归一的字符串 Query，`NaN` / `Infinity` 继续传递，以及只处理成功分支的请求。

## FB03：异步时序与资源生命周期

请求、提交、定时器、订阅和事件监听应处理重复触发、竞态、取消或卸载后的回调，以及对应清理。

重点检查遗漏 `await` 或 rejection、旧请求覆盖新结果、重复提交、effect 内注册资源无 cleanup、组件卸载后仍更新状态。

## FB05：状态与渲染语义

修改 props、入参、共享对象或状态时保持不可变更新；异步闭包和 effect 依赖应使用当前值；条件渲染应明确 `0`、空字符串和 `NaN` 的业务语义。

重点检查原地修改导致浅比较失效、依赖前值却未使用函数式更新、`useEffect([])` 捕获变化值、依赖项使用新建对象导致循环执行，以及 `{count && <Comp />}` 意外渲染 `0`。

## FB06：计算与边界语义

金额、时间、数值、集合边界和条件分支应覆盖异常输入，避免隐式时区、浮点精度、非法数值和越界结果进入后续链路。

重点检查金额浮点计算、时间字符串或本地时区假设、`Number.isFinite` 缺失、循环边界错误、错误的 `NaN` 判断和高阶数组回调遗漏返回值。
