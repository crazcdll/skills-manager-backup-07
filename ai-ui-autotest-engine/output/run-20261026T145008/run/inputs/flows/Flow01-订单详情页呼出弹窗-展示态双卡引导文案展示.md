# Flow01 · 订单详情页呼出弹窗-展示态双卡引导文案展示

<!-- caseId = 4210287 -->

> 关联 EC 用例：4210287（P0：【订单详情页】呼出弹窗-展示态双卡引导文案-文案常驻展示）
> 执行类型：data-dependent
> 前置条件：已预订国内酒店订单（已支付、未入住/未取消、可联系酒店状态），酒店已开通隐私号能力；覆盖矩阵：美团App/点评App × 安卓/iOS/鸿蒙（多端执行时替换 {order_id} 重复跑）

> 测试数据参考：EC 用例未提供具体订单号，执行时使用可联系酒店状态的国内酒店测试订单（订单构造见 workspace `testplan/testdata.md` 订单 #1）

## 落地入口

```
imeituan://www.meituan.com/mrn?mrn_biz=hotel&mrn_entry=hotelchannel-order-detail&mrn_component=hotelchannel-order-detail&order_id={order_id}&biz_type=1
```

## 执行步骤

### S1. 滚动到联系酒店入口

**操作**：滚动到「联系酒店」。

**等待**：订单详情页加载完成，「联系酒店」入口可见。

**校验**：
- 「联系酒店」 — 渲染就绪标志

### S2. 点击联系酒店唤起号码呼出弹窗

**操作**：点击「联系酒店」。

**等待**：号码呼出弹窗展示。

**校验**：
- 「将使用该号码加密呼出」 — 文案断言
- 「为保证服务质量，您的通话可能被录音」 — 文案断言

**接口断言**：`POST /hotelorder/v1/queryuserinfo.json`
- error.code=200，data.maskMobile（掩码本机号，如 188****1234）正常返回供弹窗展示态使用

### A1. queryuserinfo 接口返回校验

- 接口 `POST https://apihotel.meituan.com/hotelorder/v1/queryuserinfo.json` 返回 error.code=200
- data.maskMobile 非空，与弹窗号码区展示的掩码号码一致

### S3. 查看展示态弹窗双卡引导文案

**操作**：无（已在页面）。

**等待**：弹窗内容渲染完成。

**校验**：
- 「双卡双待请确认，系统呼出号码和下方一致」 — 文案断言
- 「双卡双待请确认，系统呼出号码和下方一致」位于「将使用该号码加密呼出」正下方、号码区上方 — 视觉确认
- 「双卡双待请确认，系统呼出号码和下方一致」字号/色值与 UI 稿一致（12pt/#999999/居中） — 视觉确认
- 「非本机号请修改」 — 文案断言
- 「立即呼叫」 — 文案断言
- 「取消」 — 文案断言

**证据要求**：对展示态弹窗整体截图一张（含标题、双卡文案、号码区、按钮），供样式走查对照 UI 稿 https://imd.sankuai.com/goto/WXY9Zrqp

### S4. 关闭弹窗

**操作**：点击「取消」。

**等待**：弹窗关闭。

**校验**：
- 「将使用该号码加密呼出」消失 — 文案消失

### S5. 再次唤起弹窗检查文案常驻展示

**操作**：点击「联系酒店」。

**等待**：号码呼出弹窗再次展示。

**校验**：
- 「双卡双待请确认，系统呼出号码和下方一致」 — 文案断言
