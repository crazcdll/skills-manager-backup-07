# 维度 6：业务领域建模（14%，L4）

**核心原则**：必须区分"有文件"与"有内容"——空模板、内容极少的占位文档大幅扣分。
**隐含规则**（老研发知道但文档没有的东西）是 AI 最容易踩坑的地方，是此维度的核心考察点。

## 量化定义（消除主观歧义）

在评分前，先对以下术语做量化判定：

| 术语 | 量化标准 |
|------|---------|
| **充实** | 后端：有效内容行数 ≥ 100 行（去除空行、纯注释行、分隔符后）；前端：≥ 200 行 |
| **内容极少** | 有效内容行数 < 50 行，或文档中 ≥ 60% 是骨架标题/TODO/占位符 |
| **隐含规则已显性化** | 文档中存在 ≥ 3 条以"禁止/不能/注意/特殊/例外/只有在…时才"开头的具体约束句，且每条有明确的业务原因说明 |
| **有具体边界** | 对业务概念的定义包含：①是什么、②不是什么（排除情况）、③边界值举例，三者至少具备两项 |
| **私有术语表存在** | 文档中有 ≥ 5 个项目特有名词（非通用技术词汇）的释义 |

## 评估标准（通用）

- [ ] **领域文档存在且充实**（后端有效内容 ≥ 100 行；前端 ≥ 200 行；见上方量化定义）
- [ ] **核心业务概念有清晰定义**（满足"有具体边界"量化定义：是什么 + 不是什么 + 边界值举例，至少两项）
- [ ] **业务流程有完整描述**（含分支条件、异常路径；流程中每个分支均有说明）
- [ ] **私有术语表/名词表存在**（≥ 5 个项目特有名词释义）
- [ ] **隐含规则已显性化**（≥ 3 条含业务原因的具体约束句；见上方量化定义）
- [ ] 枚举/常量值定义完整（含业务含义，非仅技术定义）
- [ ] 边界条件与异常情况有说明
- [ ] FAQ / 问题排查指南存在

## 评分细则（通用）

| 分段 | 描述 | 量化判定依据 |
|------|------|------------|
| 90–100 | 领域建模完整，隐含规则已显性化，有流程文档、FAQ，内容充实 | 有效内容 ≥ 100/200 行 + 隐含规则 ≥ 3 条 + 术语表 ≥ 5 条 + 流程文档存在 |
| 75–89 | 领域文档存在，内容有实质价值，但隐含规则覆盖不全 | 有效内容 ≥ 100/200 行 + 隐含规则 1–2 条（或无业务原因说明） |
| 60–74 | 有基础业务描述，但缺乏结构化，内容较浅 | 有效内容 50–99/50–199 行，或概念定义缺少边界说明 |
| 30–59 | 文件存在但内容极少，或为空模板 | 有效内容 < 50 行，或 ≥ 60% 是骨架标题/TODO/占位符 |
| <30 | 无业务领域文档 | 无任何领域相关 .md 文件，或仅有外部链接无本地内容 |

### 评分锚点示例

**90 分样本（高分）**：
```
.mdp/context/order-domain.md（有效内容 156 行）
- 包含"订单状态机"完整流程图（文字版），每个状态转换均有触发条件
- 包含"隐含规则"章节：
  "禁止在支付回调中直接修改库存，原因：分布式事务未接入，只能通过异步消息"
  "注意：退款只能在订单完成后 7 天内发起，超期走人工审核"
  "特殊：大促期间限购规则由运营动态配置，不在代码中硬编码"
- 包含术语表：核销、履约、逆向单、sku、spu、商品池……共 12 条
```

**70 分样本（中分）**：
```
docs/business.md（有效内容 80 行）
- 有基础业务描述，但概念定义缺少"不是什么"的排除说明
- 无隐含规则章节，老研发知道的约束未文档化
- 术语表仅 2 条，不满足 ≥5 条阈值
- 有流程描述但异常路径未覆盖
```

**30 分样本（低分）**：
```
.mdp/context/domain.md（有效内容 20 行）
内容仅为：
# 业务说明
本系统负责订单管理。
## TODO
- [ ] 补充业务流程
- [ ] 补充术语表
（典型空模板，≥ 60% 是占位符）
```

> ⚠️ **重要**：外部链接（如学城 km.sankuai.com）对 AI 不可见，不计入得分。领域知识必须本地化。

## 技术栈执行指南

> 根据 REPO_TYPE 选择对应列的检查命令执行。

| 检查项 | backend（Java/Maven） | frontend/frontend-mono（TS/JS） |
|--------|----------------------|--------------------------------|
| 领域文档位置 | `find .mdp/context/ -name "*.md" -type f 2>/dev/null` | `find docs/ .catpaw/rules/ -name "*.md" -type f 2>/dev/null; ls .cursorrules 2>/dev/null` |
| 文档行数（识别空模板） | `find .mdp/context/ -name "*.md" -type f 2>/dev/null \| while read f; do echo "$(wc -l < "$f") $f"; done \| sort -n` | `find docs/ -name "*.md" -type f 2>/dev/null \| while read f; do echo "$(wc -l < "$f") $f"; done \| sort -n; wc -l .cursorrules 2>/dev/null` |
| 隐含规则关键词密度 | `grep -r "注意\|禁止\|不能\|必须\|只有\|特殊\|例外" .mdp/context/ --include="*.md" 2>/dev/null \| wc -l` | `grep -rn "注意\|禁止\|不能\|必须\|❌\|⚠️\|特殊\|例外" docs/ .cursorrules .catpaw/rules/ 2>/dev/null \| wc -l` |
| 术语表 | `grep -r "术语\|名词表\|glossary\|私有名词" . --include="*.md" 2>/dev/null \| wc -l` | `grep -rn "术语\|名词\|glossary\|定义" docs/ .cursorrules 2>/dev/null \| wc -l` |
| 枚举/常量注释 | `grep -rn -A2 "enum " . --include="*.java" 2>/dev/null \| head -30` | `grep -rn "// \|/\*\*" . --include="*.ts" 2>/dev/null \| grep -i "const \|enum " \| head -20` |
| 流程文档 | `find . -name "*process*.md" -o -name "*流程*.md" 2>/dev/null` | `find docs/ -name "*flow*" -o -name "*流程*" -o -name "*process*" 2>/dev/null` |
| FAQ | `find . -name "*faq*.md" -o -name "*FAQ*.md" 2>/dev/null` | `find docs/ -name "*faq*" -o -name "*FAQ*" 2>/dev/null` |

## 结构性差异说明

- **后端**：领域文档内容阈值 ≥ 100 行（`.mdp/context/*-domain.md`）
- **前端**：领域文档内容阈值 ≥ 200 行（因前端业务流程涉及更多交互状态、路由逻辑、UI 约束）；文档位置为 `docs/`、`.cursorrules`、`.catpaw/rules/` 等
