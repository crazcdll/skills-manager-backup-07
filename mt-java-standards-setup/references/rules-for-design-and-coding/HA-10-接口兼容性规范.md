# 接口兼容性规范

## 一、说明

本规范定义了接口变更的兼容性标准，聚焦版本管理领域。接口兼容性故障占 COE 的 9.4%，是高可用体系中极易被忽视但影响巨大的领域。一次不兼容的接口变更可能导致所有调用方解析失败。

> 边界划分：本规范聚焦「接口怎么变」（版本共存、灰度切流）；接口的结构设计（返回值封装、分页、参数设计）详见 `JAVA-08-接口设计规范.md`。

## 二、规则内容

### HA-API003 [推荐] 接口版本管理建议有序

接口变更建议按版本管理，新旧版本共存至少 2 个迭代周期。

**说明**：
- 大版本变更（不兼容变更）建议使用新的接口路径或版本号
- 灰度发布按调用方逐步切流，不建议一次性全量切换
- 版本切换前建议确认所有调用方已适配

### HA-API004 [强制] Thrift IDL 变更必须保持向后兼容

对已发布的 Thrift IDL，禁止修改或删除已有服务名、方法名和字段；字段 ID、枚举值必须保持唯一且不可变。`optional` 字段禁止改为 `required`，存量结构体新增字段必须使用 `optional`。

**说明**：
- 禁止修改或删除已有服务名、方法名；需要调整时必须新增服务或方法替代旧定义
- 禁止修改或删除已有字段，禁止修改字段 ID；新增字段不得复用已删除字段的 ID
- 枚举值必须唯一；新增枚举值必须使用未占用的值，不得修改已有枚举值
- 禁止将已有 `optional` 字段修改为 `required`；该变更会使未升级调用方因未传字段而调用失败
- 存量结构体新增字段必须标记为 `optional`，避免未升级调用方序列化或反序列化失败

#### good case:

```thrift
service OrderService {
    Order getOrder(1: i64 orderId)

    // 新增方法替代原有方法，不修改或删除 getOrder
    Order getOrderV2(1: i64 orderId, 2: optional bool withDetail)
}

enum OrderStatus {
    PENDING = 1,
    COMPLETED = 2,
    CANCELED = 3 // 使用未占用的枚举值新增
}

struct Order {
    1: required i64 orderId,
    2: optional string status,
    3: optional string remark // 存量结构体新增字段必须 optional
}
```

#### bad case:

```thrift
service OrderService {
    // 删除或改名已有 getOrder，未升级调用方会调用失败
    Order queryOrder(1: i64 orderId)
}

enum OrderStatus {
    PENDING = 1,
    COMPLETED = 1 // 枚举值重复
}

struct Order {
    1: required i64 orderId,
    2: required string status // 原 optional 字段改为 required
    // 删除已有字段或修改字段 ID 也会破坏兼容性
}
