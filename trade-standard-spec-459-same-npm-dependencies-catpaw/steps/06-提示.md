## 🎯 执行内容

### 步骤 1: 将 .spec 加入 .gitignore

检查项目根目录下的 `.gitignore` 文件，若尚未包含 `.spec`，则追加：

```
# trade-standard-npm-same-version skill 工作目录（不提交）
.spec/
```

### 步骤 2: 重点提示 @mtfe/msi-mrn 和 @mtfe/msi 版本升级

提醒用户：
> ⚠️ **重点关注 `@mtfe/msi-mrn` 和 `@mtfe/msi` 的版本升级**
>
> 对于跨端项目（含 H5 端），升级这两个包后，**H5 侧可能出现兼容性问题**，请在 H5 环境下充分测试后再合并到主干。

### 步骤 3: 提示用户重点检查 package.json 改动

提醒用户仔细核对 `package.json` 中的版本改动是否符合预期，特别是：
- 是否有非预期的版本升级或降级。
- `resolutions` 中的锁定版本是否与 `dependencies` 一致。
- 从 `oh-package.json` 迁入的依赖是否正确写入对应字段。

### 步骤 4: 根据 changelist 总结改造内容

读取 `.spec/result/changelist.md` 的内容，向用户输出简洁的改造总结，包括：

1. **oh-package.json 变更**：
   - 删除（迁至 package.json）了哪些三端兼容依赖（列出包名和版本）。
   - 更新了哪些鸿蒙专属依赖的版本。

2. **package.json 变更**：
   - 新增了哪些从 oh-package.json 迁入的依赖。
   - 升级了哪些依赖版本（原版本 → 新版本）。
   - 更新了哪些 resolutions 锁定。

3. **yarn.lock 变更**：
   - 处理了哪些重复依赖。

4. **⚠️ 需要用户人工确认的项**：
   - 未在知识库中找到的依赖。
   - 知识库三端兼容版本为空的依赖（只兼容 Android/iOS）。
   - 版本未升级（当前版本已高于或等于标准版本）的依赖。

输出格式示例：
```
## ✅ 三端一致性改造完成

### oh-package.json
- 删除（迁至 package.json）：@max/meituan-uni-knb、@max/meituan-uni-payment（共 N 个）
- 版本更新（鸿蒙专属）：@mrn/mrn-cli 4.0.0-beta.26 → 4.0.1

### package.json
- 新增（从 oh-package.json 迁入）：@max/meituan-uni-knb ^2.0.14、@max/meituan-uni-payment ^1.0.5
- 版本升级：@max/meituan-uni-base 1.0.0 → ^1.2.0
- resolutions 更新：@some/pkg 锁定为 2.0.0

### yarn.lock
- 清理重复依赖：@some/pkg（1.0.0/2.0.0 → 统一 2.0.0）

### ⚠️ 需要人工确认
- @some/unknown-package：未在知识库中找到，请人工核查是否需要处理
- @some/package：三端兼容版本为空，目前仅支持 Android/iOS，请关注鸿蒙侧兼容性

### 提醒
- ⚠️ 请重点关注 @mtfe/msi-mrn 和 @mtfe/msi 升级后在 H5 端的兼容性
- 已将 .spec/ 加入 .gitignore
```
