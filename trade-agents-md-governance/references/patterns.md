# AGENTS.md 分层模式与模板

仅在需要新建或重构规则文件时读取。模板是结构参考，不得原样批量复制；没有真实内容的条目应删除。

## 内容分类表

| 类型 | 典型内容 | 默认去向 |
| --- | --- | --- |
| 可执行约束 | 禁改生成物、发布前置、验证门槛、授权边界 | 当前作用域 `AGENTS.md` |
| 导航索引 | 目标页面、源码目录、权威知识入口 | 根或当前工作单元 `AGENTS.md` |
| 当前实现事实 | 依赖版本、API、字段、组件、状态机、目录数量 | 源码、manifest、生成型 reference |
| 跨仓业务知识 | 术语、跨页面流程、ownership、跨仓 ADR | 中央知识库或专用 Skill |
| 阶段性记录 | 当前需求、进度、设计尺寸、临时 Mock | 需求文档、设计稿、Git 历史或任务记录 |

## 根级路由模板

适用于 Monorepo、多页面仓库或包含多个独立工作单元的工程。

```markdown
---
scope: <repository>
authority: routing
owner: <team-or-unknown>
---

# <repository>

<一至两句工程定位和根文件职责。>

## 工作路由

- 处理 <scope-a> 时进入 `<path-a>`，读取该目录规则和当前源码。
- 处理 <scope-b> 时进入 `<path-b>`，不得套用兄弟目录结论。
- 业务知识与通用编码规范由专用 Skill 按任务意图加载。

## 仓库级边界

- <真正对所有子级成立的修改或授权边界。>
- <公共能力变更时必须执行的影响面动作。>

## 维护规则

- 仅在路由、修改边界或验证门槛变化时更新。
- 自动化只告警或提出候选修改，正文必须人工审核。
```

根文件不要列全量页面说明、全部命令或通用 Git 模板。若子页面没有共同约束，根文件保持纯路由。

## 独立页面或包模板

适用于页面、包或其他独立工作单元，由独立团队维护，或需要在不读取兄弟目录的情况下独立指导任务。

```markdown
---
scope: <package-or-directory>
authority: execution-contract
owner: <team-or-unknown>
---

# <package-or-directory>

本文件是 <页面或包职责> 的完整行动契约，只约束当前目录。

## 工作范围与权威来源

- 在本目录工作；脚本、依赖和平台能力以当前 manifest、锁文件和配置为准。
- 从入口与路由确认目标链路；旧 README 或自动总结只作参考。

## 必须遵守

- 当修改 <高风险链路> 时，必须贯通检查 <触发到副作用>。
- <历史拼写、外部发布或真实数据等非显然风险。>
- 涉及代码边界或统一入口时，给出可核验的真实路径。

## 验证与完成标准

- 从当前 manifest 确认检查方式，不复制普通命令清单。
- 覆盖成功、失败、空态、重复操作、恢复路径和受影响平台。
- 无法验证时列出原因、范围和补验方式。

## 维护规则

- 只在行动边界、风险或验证门槛变化时更新。
- 不同步代码结构、字段和当前需求快照。
```

`authority` 必须选择单一职责：纯路由文件写 `routing`，包含当前作用域强约束的完整行动契约写 `execution-contract`。不要原样写成 `execution-contract | routing`。

## 生成物工程模板

根文件必须明确三件事：

1. 哪些路径是手写源码。
2. 哪些路径是生成结果，只能用于排查。
3. 生成、覆盖、发布或真实业务写入需要什么授权。

```markdown
## 工作路由

- 协议或配置修改在 `<source-path>` 完成。
- 组件或物料修改在 `<component-source-path>` 完成，并读取子级规则。
- 构建器或生成流程仅在用户明确要求时执行。

## 必须遵守

- `<generated-path>` 禁止手工修改；修复必须回到对应源码。
- 契约变化必须同步检查类型、schema、调用方和发布引用。
- ID、版本和依赖映射必须通过当前工具与 manifest 核实，不得复用历史快照。
```

## 独立物料或组件目录模板

只保留该目录独有的契约与发布生命周期：

- props、事件、ref、类型和 schema 的联动范围。
- 发布物料后平台何时才能使用新契约。
- 聚合 Lint 是否包含自动修复或依赖修改。
- 多端验证不能互相替代的边界。
- 生成目录与手写目录的精确关系。

不要写某次业务需求的字段、样式数值、模式枚举或 UI 稿结论。

## Webhook 候选变更格式

Webhook 输出至少包含：

```markdown
### 受影响规则

- 文件与条目：<AGENTS.md 中的具体规则>
- 变化证据：<commit + source/manifest path>
- 影响判断：为何可能失效，是否改变 Agent 行动
- 建议动作：保留 / 删除 / 改写 / 降级为索引
- 审核人：<owner>
```

没有具体受影响条目和证据时，只生成“无需更新”的审计结果，不创建占位 PR。

## 反例

以下内容看似有帮助，实际不应常驻：

- “本仓库共有 44 个组件”。数量会漂移，Agent 可实时统计。
- “当前使用 React X.Y”。依赖和锁文件更可靠。
- “本期字段缺失时按某模式处理”。这是业务契约或阶段性实现，应回到权威来源。
- “所有页面统一运行某命令”。单仓多页面项目的脚本可能不同。
- “某功能已经完成 80%”。属于任务进度，不是下次编码必须看到的约束。
