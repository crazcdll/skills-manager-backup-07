# MSI 使用情况走查（多项目复用）

在项目业务代码（默认 **`src/`**）中检索**直接调用 MSI API** 的代码，对照 KNB→MSI 迁移说明文档逐项检查，产出结构化报告。仅关注业务代码中的直接引入与调用，通过封装层间接使用可忽略。**仅走查并记录结论，不在此 skill 内修复代码。**

## 范围与规范

- **检索范围**：以 **`src/`** 为主；若入口或配置中也有 MSI 调用可一并纳入。排除 `node_modules`、构建产物。
- **规范定义**：「符合规范」指当前代码对 MSI 的调用方式、参数、返回值处理与对应 KM 迁移说明文档一致，无遗漏或错误用法。
- **迁移说明文档表**：见本 skill 内 [migration-docs.md](migration-docs.md)，执行前读取该文件获取完整 KNB→MSI 映射与 KM 链接。

## 执行顺序

1. 在 `src/` 中全文检索 MSI 的直接调用（如 `MSI.`、`from 'msi'`、`import MSI`、`@mtfe/msi-mrn` 等，忽略大小写），去重得到「用到的 API 列表」。
2. 将用到的 API 分为两类：在 [migration-docs.md](migration-docs.md) 迁移表中的（有文档）和不在表中的（无文档）。
3. 按 API 功能类别分批处理；对每批打开对应 KM 文档（使用 **intranet-browser** 访问 `km.sankuai.com`），阅读迁移说明。
4. 对照文档检查代码中的调用方式，记录「符合」或「待修改」及原因。若 KM 文档无法访问，**直接终止任务**并说明。
5. 将结果整理为报告，输出到 **`scan_tmp/REPORT.md`**；中间状态按「暂存约定」写入 **`scan_tmp/`**。

## 合规检查注意（避免漏报）

执行「对照文档检查」时，请**逐 API、逐调用点**按下面要点核对：

- **按调用点检查，不合并结论**：同一 API 的多次调用，每个调用点都要单独看入参、回调和下游使用。
- **入参严格按文档「入参差异」表**：参数名、个数和取值以**迁移文档中规定的目标 API（MSI）为准**，不能沿用 KNB 的命名或习惯。
- **出参/回调按文档「出参差异」表**：回调对象的**字段名与层级**以文档为准，代码中的解构、属性访问必须与文档一致。
- **追踪「回调传出内容」与「下游使用」**：若结果会传给别处（如 `resolve(...)`、Promise.then、setState、props），必须追踪**下游对该结果的字段访问**，确认与文档规定的出参结构一致。

## 产出与暂存

- **报告**：`scan_tmp/REPORT.md` 至少包含：
  - 项目中使用的 MSI API 列表及每个 API 的调用位置（文件 + 行号或片段）；
  - 每个 API 对应的迁移文档链接及合规结论（✅ 符合 / ⚠️ 待修改 + 简要说明）；
  - 不在迁移表中的 API 单独列出（📋 无对应迁移文档）。
- **暂存**：中间状态（已检查 API、进度、草稿结论）写入 **`scan_tmp/`**；可注明最后更新时间、已检查/待检查的 API、问题摘要。

## 依赖与工具

- **内网文档**：KM 链接为 `km.sankuai.com`，需使用 **intranet-browser**（或 agent 浏览器）打开。
- **环境**：使用浏览器相关能力前请先执行 **`nvm use 22`**。
- **文档快照**：用 agent-browser snapshot 获取 KM 页完整 DOM 快照；正文从第一个 `heading "KNB xxx 到 MSI xxx 映射关系文档"` 开始，以该正文区的 heading/paragraph/table/list/code 为准，表格以结构化 table/cell/row 形式出现，可直接用于对照与合规检查。
