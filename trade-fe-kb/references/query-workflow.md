# 查询流程详细指引

## 总览

```
用户输入问题
  → [公共前置] clone/pull ~/.trade-fe-kb
  → Read AGENTS.md（路由表，必读）
  → 意图识别 → 确定业务组 + 加载层级
  → Read _index.md → 跟随 related 字段递归加载
  → 生成答案
```

---

## Step 1：公共前置

见 `SKILL.md` §第一步，确保 `~/.trade-fe-kb` 已同步到 `release/main` 最新代码后再继续。

---

## Step 2：读取路由表（必须，不可跳过）

```
Read ~/.trade-fe-kb/AGENTS.md
```

AGENTS.md 是唯一路由依据，包含：

- §0.3 意图识别与加载策略（六类任务意图 + 对应加载文件）
- §0.4 四条硬约束

读取完成后，**以 AGENTS.md 中的规则为准执行后续步骤**，本文件不重复定义意图表，仅作操作步骤补充。

---

## Step 3：意图识别与业务组确认

> **两层意图识别的职责分工（重要）**：
> - **SKILL.md P1-P5 优先级表**：用于区分"是查询还是更新"，已在 SKILL.md 阶段完成，进入本流程说明已确认为查询意图。
> - **AGENTS.md §0.3**：用于确定"查询时加载哪些 KB 文件"，是文件路由依据，**不再重新判断 query/update 意图**。

**文件路由**：按 AGENTS.md §0.3 的六类任务意图信号词匹配，确定加载目标文件列表。

**业务组识别**：从用户问题中提取业务方向关键词：

| 关键词 | 业务组目录 |
|-------|----------|
| food、到餐、美食、团购、核销、买单 | `biz/food/` |
| gc、到综、服务零售、丽人、次卡、预约 | `biz/gc/` |
| ticket、景点、门票、游玩、电子票 | `biz/ticket/` |
| hotel、酒旅、酒店、价格日历、入住 | `biz/hotel/` |
| platform、DUO、低代码、组件库、基础设施 | `biz/platform/` |
| 跨业务/通用问题 | `biz/general/` + `L0-rules/` |

若无法从问题判断业务方向，**主动询问用户**属于哪个业务组后再继续。

---

## Step 4：文件加载

### 4.1 读取业务组入口

```
Read ~/.trade-fe-kb/biz/<group>/_index.md
```

`_index.md` 包含该组的文件路由规则表，是进入具体文件前的必读入口。

### 4.2 按意图加载目标文件

按 AGENTS.md §0.3 确定的文件列表逐一 Read。文件数量超出上限时，优先读层级更高（L0 > L1 > L2）的文件。

### 4.3 跟随 related 字段递归加载（最多 2 层）

读取任何文件后，**必须检查其 frontmatter 的 `related:` 字段**，递归加载伴生文件。

路径解析规则：`related:` 中的路径相对于**当前文件所在目录**。

```yaml
# 示例：读 biz/gc/L2-spec/domain-models/state-machines.md 后
related:
  - enums.md                    # → biz/gc/L2-spec/domain-models/enums.md
  - ../L1-domain/glossary.md    # → biz/gc/L1-domain/glossary.md
```

### 4.4 四条硬约束（违反则答案无效）

1. **禁止枚举 biz 目录**：不得用 find/glob 遍历 biz 目录，必须按路由表定位文件
2. **禁止跨组读取**：确定业务组后，只读该组目录下的文件（L0-rules 除外）
3. **跟随 related 字段**：每个文件读完必须跟进 related 中的伴生文件（最多 2 层）
4. **禁用训练知识**：所有字段名、状态码、业务规则必须来自实际读取的文件内容

---

## Step 5：生成答案

**格式要求**：

- **结论先行**：首句给出直接答案，再展开细节说明
- **过期提示**：若引用文件的 frontmatter 有 `expires_at` 且已过期，在答案末尾加注：
  ```
  ⚠️ 部分内容可能已过期（expires_at: <日期>），请向负责人（owner: <mis>）确认
  ```

**找不到相关内容时**，输出：

```
在知识库中未找到关于「<用户问题>」的内容。
可能原因：
1. 内容尚未录入知识库
2. 属于其他业务组（你的问题属于哪个业务方向？）
3. 内容在 _governance/ 目录中（供人工维护，不进入 Agent 上下文）

建议：通过 /trade-kb update 将相关规范录入知识库。
```
