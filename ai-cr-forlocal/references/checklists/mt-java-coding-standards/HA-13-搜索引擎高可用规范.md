# 搜索引擎高可用规范

## 一、说明

本规范定义了搜索引擎（Eagle/ES）操作的高可用标准，涵盖查询安全、写入安全、Mapping 管理和容灾降级四个领域。ES 集群资源有限，不当的查询或写入操作可能导致集群不可用，影响所有使用该集群的服务。

## 二、规则内容

### java-l1:HA-13.HA-ES001 [推荐] 查询建议安全

ES 查询建议控制资源消耗，防止慢查询拖垮集群。

**说明**：
- 不建议 `from + size > 10000` 的深分页，建议使用 `search_after` 或 `scroll` 替代
- 不需要评分的查询使用 `filter` 替代 `must`（filter 有缓存，性能更好）
- 精确匹配使用 `term` + `keyword` 类型字段，不建议对 `text` 字段做精确查询
- `terms` 查询元素数量 ≤1024
- 聚合查询 `size` ≤65536
- `scroll` 查询使用后建议及时清理（`DELETE /_search/scroll`）

### java-l1:HA-13.HA-ES002 [推荐] 写入建议安全

ES 写入建议使用 Bulk 批量操作，且保证幂等。

**说明**：
- 写入建议使用 Bulk API，不建议逐条写入
- Bulk 请求体大小 ≤10MB
- 指定文档 id 写入（幂等），不建议使用自动生成 id
- Bulk 写入的失败项建议处理（检查 response 中每条的状态）

### java-l1:HA-13.HA-ES003 [推荐] Mapping 变更建议安全

已有字段的类型不建议修改，副本数建议 ≥1。

**说明**：
- ES 不支持修改已有字段的 Mapping 类型，变更需要重建索引
- 新增字段注意 `index` 属性的设置（不需要检索的字段设置 `index: false`）
- `refresh_interval` 根据实时性要求设置，非实时场景建议 30s
- 生产索引副本数建议 ≥1

### java-l1:HA-13.HA-ES004 [推荐] ES 建议有容灾降级

ES 操作建议有容灾降级能力。

**说明**：
- 通过 Lion 开关控制 ES 切流（如切到 DB 兜底查询或缓存）
- 配置 Raptor 告警：查询延迟、错误率、集群健康状态
- 关闭 ES 客户端的自动重试（防止故障时重试风暴）
- ES 不可用时，降级路径不建议阻断核心业务

## 三、实践建议

1. ES 查询建议避免深分页
2. 写入建议使用 Bulk 且指定文档 id
3. 不建议修改已有字段的 Mapping 类型
4. 建议配置 ES 容灾降级和告警

## 四、示例

以下示例仅用于说明规则边界与意图，不代表唯一实现方式；实际生成或审查代码时，应优先复用项目现有框架、工具类、SDK 与命名，并以是否满足规则约束为判断标准。

### java-l1:HA-13.HA-ES001 查询安全示例

#### good case:

```java
// search_after 替代深分页
SearchRequest request = new SearchRequest("order_index");
SearchSourceBuilder builder = new SearchSourceBuilder()
    .query(QueryBuilders.termQuery("status", "completed"))
    .size(100)
    .sort("_id", SortOrder.ASC)
    .searchAfter(lastSortValues); // 使用上一页最后的排序值
request.source(builder);
```

#### bad case:

```java
// 深分页 — from + size > 10000 会导致 ES OOM
SearchSourceBuilder builder = new SearchSourceBuilder()
    .query(QueryBuilders.matchAllQuery())
    .from(50000)
    .size(100);
```

## 五、规范执行要点

### 推荐要点
1. **查询**：不建议深分页，filter 替代 must，terms ≤1024
2. **写入**：Bulk 批量写入，指定文档 id，≤10MB
3. **Mapping**：不建议修改已有字段类型，副本 ≥1
4. **容灾**：Lion 切流，Raptor 告警，关闭客户端重试

### 不建议做法
- ✗ 不建议 `from + size > 10000`
- ✗ 不建议对 text 字段做精确匹配
- ✗ 不建议逐条写入 ES
- ✗ 不建议 Bulk 请求体超过 10MB
- ✗ 不建议修改已有字段的 Mapping 类型
- ✗ 不建议 ES 不配置容灾降级

### 代码审查检查点
- [ ] 查询是否存在深分页（from + size > 10000）
- [ ] 不需要评分的查询是否使用了 filter
- [ ] terms 元素是否超过 1024
- [ ] 写入是否使用 Bulk 且指定了文档 id
- [ ] Bulk 失败项是否有处理逻辑
- [ ] 是否配置了 ES 容灾降级开关
- [ ] scroll 查询是否及时清理
