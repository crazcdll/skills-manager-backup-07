# 小程序代码审查基础规范

> 适用于微信、支付宝、抖音等小程序项目。
> `base` 层已覆盖通用与交易基础规则；本文件只补充小程序特有运行时、渲染性能、容器约束和平台差异。
> **等级说明**：**高**为建议阻塞合并或必须修复；**中**为建议优化或需在 PR 中说明依据；**低**为可优先交给静态工具检查，AI 仅在项目无 Lint 配置或规则明显缺失时作为兜底报告。
> 
> 更新时间：2026.4.23

## 一、性能规范

### M01 setData 调用优化
- **等级**：高
- **描述**：setData 是小程序性能的关键瓶颈，必须优化调用频率和数据量
- **规则**：
  - 避免频繁调用 setData，合并多次 setData 为一次
  - 避免 setData 传递大量数据，只传递变更的字段
  - 使用数据路径更新代替全量更新
- **正例**：
```js
// 只更新变更的字段
this.setData({ 'list[0].name': 'new name' });
// 合并多次更新
this.setData({ name: 'test', age: 18, status: 'active' });
```
- **反例**：
```js
// 全量更新大对象
this.setData({ allData: this.data.allData });
// 循环中频繁调用
for (let i = 0; i < list.length; i++) {
  this.setData({ [`list[${i}].checked`]: true }); // 应合并为一次
}
```

### M02 避免 setData 传递非渲染数据
- **等级**：高
- **描述**：setData 会触发视图层渲染，不参与渲染的数据不应通过 setData 设置
- **正例**：
```js
// 非渲染数据直接挂载到实例
this._timer = setTimeout(() => {}, 1000);
this._cache = {};
```
- **反例**：
```js
// 非渲染数据通过 setData 设置
this.setData({ timer: setTimeout(() => {}, 1000) });
this.setData({ cache: {} });
```

### M03 图片资源优化
- **等级**：高
- **描述**：图片是小程序包体积和加载性能的主要影响因素
- **规则**：
  - 优先使用 CDN 图片、尺寸裁剪和质量参数控制，避免大图直接进包
  - 本地图片仅用于必要静态资源，避免大量业务图片随包发布
  - 列表中的图片使用懒加载 `lazy-load`
  - 避免使用过大的图片（建议单张不超过 200KB）
- **正例**：
```html
<image src="{{imgUrl}}" lazy-load mode="aspectFill" />
```

### M04 长列表性能优化
- **等级**：高
- **描述**：长列表渲染是小程序常见的性能问题
- **规则**：
  - 使用虚拟列表或分页加载
  - 避免一次性渲染大量列表项，必要时分片渲染或按视口增量加载
  - 列表项使用稳定的 `wx:key` 提供唯一标识，避免索引 key 导致状态错位
- **正例**：
```html
<view wx:for="{{displayList}}" wx:key="id">{{item.name}}</view>
```
- **反例**：
```html
<!-- 缺少 wx:key -->
<view wx:for="{{list}}">{{item.name}}</view>
<!-- 一次性渲染数百条数据 -->
```

### M05 避免不必要的重渲染
- **等级**：高
- **描述**：减少不必要的页面和组件重渲染，包括但不限于 `setData`、`observers` 和页面切回前台引起的重复渲染。
- **规则**：
  - 组件使用 `pureDataPattern` 标记纯数据字段
  - 合理使用 `observers` 代替 `watch` 中的 setData
  - 避免在 `onShow` 中无条件刷新数据

### M06 包体积控制
- **等级**：中
- **描述**：小程序存在主包、分包和下载体积限制（微信小程序主包不超过 2MB，总包不超过 20MB），需关注是否把大依赖、静态资源或低频功能错误放入首包。
- **规则**：
  - 首包只保留首屏和高频路径所需资源，低频页面和重模块优先拆分到分包
  - 避免引入体积大但使用面窄的第三方库
  - 静态资源优先走 CDN，避免把大量图片、字体、配置随包发布

### M07 首屏渲染优化
- **等级**：中
- **描述**：首屏渲染速度直接影响用户体验
- **规则**：
  - 使用骨架屏提升感知速度
  - 首屏关键数据应尽早在 `onLoad` 中发起，不要等到页面完全 ready 后才开始请求
  - 避免首屏同步执行明显耗时的计算、遍历和数据拼装
  - 合理使用数据预拉取和周期性更新

## 二、数据管理规范

### M08 数据层级扁平化
- **等级**：低
- **描述**：`data` 结构应尽量保持可维护，避免为频繁更新的数据设计过深嵌套，增加 `setData` 路径更新和状态维护成本。
- **正例**：
```js
data: {
  userName: '',
  userAge: 0,
  orderStatus: ''
}
```
- **反例**：
```js
data: {
  user: {
    info: {
      basic: {
        name: '',
        age: 0
      }
    }
  }
}
```

### M09 全局数据管理
- **等级**：中
- **描述**：跨页面共享数据应有明确归属和生命周期，避免滥用 `getApp().globalData` 或依赖页面栈隐式透传。
- **关注点**：是否滥用 `getApp().globalData`、是否有合理的状态管理方案

### M10 缓存策略
- **等级**：中
- **描述**：重点关注 Storage 的过期策略、容量和敏感信息处理，以减少网络请求。
- **规则**：
  - 缓存数据设置合理的过期时间
  - 避免缓存敏感信息
  - 注意 Storage 的容量限制（微信单个 key 上限 1MB，总上限 10MB）

## 三、安全规范

### M11 用户输入校验
- **等级**：高
- **描述**：所有用户输入必须在前端和后端同时校验
- **关注点**：表单输入是否做了长度、格式、XSS 防护等校验

### M12 敏感接口调用
- **等级**：高
- **描述**：涉及用户隐私的 API（如获取手机号、位置等）必须在用户授权后调用
- **关注点**：是否在调用前检查了授权状态、是否处理了用户拒绝授权的场景

### M13 网络请求安全
- **等级**：高
- **描述**：网络请求必须使用 HTTPS，敏感数据不通过 URL 参数传递
- **关注点**：是否有 HTTP 请求、token 是否通过 header 传递

### M14 代码保护
- **等级**：高
- **描述**：避免在前端代码中暴露密钥、凭据或敏感业务逻辑。
- **关注点**：是否有硬编码的 AppSecret、API Key 等

## 四、代码质量规范

### M15 组件化开发
- **等级**：低
- **描述**：可复用或结构复杂的 UI 模块应抽取为自定义组件，避免模板和逻辑在多个页面重复散落
- **关注点**：是否有大量重复的 WXML 模板、是否合理使用了 Component 构造器

### M16 事件处理与冒泡控制
- **等级**：中
- **描述**：小程序事件模型与 Web 不完全一致，审查时应重点关注事件冒泡控制是否符合交互预期，避免误触发或重复触发。
- **规则**：
  - 需要阻止冒泡时使用 `catch` 而非 `bind`
  - 避免在 WXML 模板中堆叠复杂内联表达式或依赖副作用的事件绑定逻辑
  - 父子节点同时绑定事件时，确认触发顺序和阻断行为符合预期
  - 事件处理函数命名建议使用 `handle` 或 `on` 前缀

### M17 生命周期时机与重复初始化控制
- **等级**：中
- **描述**：小程序页面频繁进入、返回前台和组件复用时，生命周期选择不当容易导致重复初始化、重复请求和清理遗漏。
- **规则**：
  - 首次初始化、订阅注册和一次性准备逻辑应放在 `onLoad`/`attached` 中进行
  - 页面退出或组件销毁时，应在销毁生命周期 `onUnload`/`detached` 中清理定时器、监听和临时状态
  - 避免在 `onShow` 中无条件重复初始化、重复请求或重复 `setData`

### M18 WXS 使用规范
- **等级**：低
- **描述**：WXS 仅适合作为特定性能瓶颈下的补充方案，不应成为默认实现路径。
- **关注点**：是否确实存在视图层性能瓶颈、WXS 中是否使用了受限语法、是否因引入 WXS 增加了维护复杂度

### M19 错误处理
- **等级**：高
- **描述**：网络请求和 API 调用必须有完整的错误处理
- **正例**：
```js
wx.request({
  url: '/api/data',
  success(res) {
    if (res.statusCode === 200 && res.data.code === 0) {
      // 处理成功
    } else {
      // 处理业务错误
    }
  },
  fail(err) {
    // 处理网络错误
    wx.showToast({ title: '网络异常', icon: 'none' });
  }
});
```
- **反例**：
```js
wx.request({
  url: '/api/data',
  success(res) {
    // 直接使用数据，未检查状态码和业务码
    this.setData({ data: res.data });
  }
  // 缺少 fail 回调
});
```

### M20 页面栈与路由方式选择
- **等级**：中
- **描述**：小程序页面栈容量有限，路由 API 选择不当会导致页面栈膨胀、回退行为异常或循环跳转问题。
- **规则**：
  - 页面栈上限为 10 层（微信），注意使用 `wx.redirectTo` 代替 `wx.navigateTo`
  - Tab 页面使用 `wx.switchTab` 跳转
  - 避免循环跳转导致页面栈溢出
