## DB-01 ORM规范（审查精要）

| 编号 | 规则 | 级别 |
|------|------|------|
| MT:ORM001 | 建议明确指定查询字段，避免不必要的 SELECT *（分页/JOIN/大字段表必须指定） | P2 |
| MT:ORM002 | SQL参数使用 `#{}`，禁止使用 `${}` 防止SQL注入（动态表名/列名除外+白名单） | P0 |
| MT:ORM003 | 不允许直接使用 HashMap/Map 作为查询结果集输出（动态报表除外） | P2 |
| MT:ORM004 | DAO/Mapper 层基础代码优先用代码生成工具生成，AI不应从头手写 | P2 |
| MT:ORM005 | 按项目框架选择正确的代码生成工具（MDP/XFrame），生成前先阅读对应文档 | P2 |

### 作用域说明
- Generator 自动生成的基础 CRUD 代码：**豁免** ORM001、ORM002
- AI 新增的自定义查询方法：**必须遵守** ORM001~ORM003
- Service 层及以上业务代码：**必须遵守**全部规范

### 强制禁止
- ✗ 禁止 `${}` 拼接用户输入（SQL注入风险）
- ✗ 禁止大表列表查询用 SELECT *
- ✗ 禁止用 HashMap/Map 作为查询返回类型
- ✗ 禁止 AI 从头手写 DO 类和 Mapper 基础结构

### 检查点
- [ ] 自定义查询是否指定了字段（非 SELECT *）
- [ ] SQL参数是否使用 `#{}`
- [ ] `${}` 使用处是否有白名单校验
- [ ] 返回类型是否为强类型 DO 而非 Map

→ 完整规则含示例见 mt-java-coding-standards/DB-01-ORM规范.md
