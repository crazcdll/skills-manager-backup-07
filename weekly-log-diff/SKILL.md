# 周工作日志 Diff 分析

用户每周提供若干学城日志文档（上周最后一天作为基准 + 本周每天的日志），逐日对比新增内容，输出结构化的周 Diff 报告。

## 输入规格

用户需提供：
- **基准文档**：上一周最后一天的日志（学城链接或 contentId），作为 Diff 起点
- **本周日志**：本周每天的日志（学城链接或 contentId），按日期顺序排列

典型输入示例：
- "基准是上周五 https://km.sankuai.com/collabpage/2758120615，本周是 2758120616 2758120617 2758120618 2758120619"
- 用户直接给一串 contentId，日期从小到大排列

如果用户没有明确指定哪个是"基准"，按文档日期或 contentId 数字大小升序，第一个为基准。

## 第一步：读取所有文档

使用 citadel skill（`oa-skills citadel getMarkdown --contentId <id>`）依次读取所有文档，保存到临时文件（如 `/tmp/log_<日期>.md`）。

读取前先检查 `oa-skills` 是否可用：
```bash
node -e "const cp=require('child_process'); const probe=process.platform==='win32'?'where oa-skills':'command -v oa-skills'; try{cp.execSync(probe,{stdio:'ignore',shell:true})}catch{cp.execSync('npm install -g @it/oa-skills --registry=http://r.npm.sankuai.com',{stdio:'inherit',shell:true})}"
```

从学城文档 URL 提取 contentId：
- `km.sankuai.com/collabpage/1234567890` → `--contentId 1234567890`
- `km.sankuai.com/page/1234567890` → `--contentId 1234567890`
- 纯数字字符串直接作为 contentId

## 第二步：提取可读正文

学城文档原始格式为 CitadelMD（含大量 `:::paragraph`、`:::list_item`、`:::heading` 等宏块语法）。读取后，从宏块中提取纯文本内容用于对比，忽略 nodeId、样式属性等元数据。

提取规则：
- `:::heading{level=N}` 中的文本 → 识别为标题
- `:::list_item` 中的文本 → 识别为列表项
- `:::paragraph` 中的文本 → 识别为正文段落
- `:[link]{href="..."}文字[/link]` → 提取链接文字或 href
- 忽略所有 `nodeId`、`hidden`、`indent`、`titleNodeId` 等属性

## 第三步：逐日 Diff

按顺序两两对比相邻文档（基准→Day1，Day1→Day2，…），找出每个对比中**后者相比前者新增的内容**。

Diff 策略：
- 以任务/事项为粒度，而非逐行字符串比较
- 如果某个任务在前一天已出现但后一天有新的子项、进展描述或结论，视为"新增"
- 如果某任务前一天不存在、后一天首次出现，标记为"首次出现"
- 如果两天内容完全一致，输出"无明显新增内容"，并指出有哪些细节差异（若有）
- 不输出"删除"内容（用户只关心新增）

## 第四步：输出报告

严格按照以下模板输出，不要自由发挥结构：

---

### 逐日 Diff 分析

#### <前一天日期>（<星期>）→ <后一天日期> Diff
新增内容：

**<任务名>**

- 新增：<具体新增项>
- 新增：<具体新增项>
- <首次出现此事项>（若为全新任务）

#### <前一天日期> → <后一天日期> Diff
（重复上述结构，每个 Diff 一节）

---

### 汇总表格

输出一张 Markdown 表格，行为任务名，列为"基准日期 + 本周每天日期"，每个单元格填写该天该任务的状态/结论（简短描述，≤20字）。若某任务当天无变化，填"同左"。若某任务当天不存在，填"不存在"。

| 任务 | <基准日> | <Day1> | <Day2> | ... |
|------|---------|--------|--------|-----|
| 任务A | ... | 同左 | 新增：... | ... |
| 任务B | 不存在 | 不存在 | 首次出现 | ... |

---

### 各项任务本周投入总结

对每个任务写一段话（3-6句），描述本周该任务的整体进展脉络、关键节点、当前阻塞或完成状态。按"本周投入程度从高到低"排序。

格式：
**N. 任务名（简短定性，如"本周投入最密集"/"本周全新启动"/"本周无新进展"）**
<正文段落>

---

## 注意事项

- 日期和星期从文档标题或文档内容中自动提取，无法提取时用 contentId 代替
- 任务名以文档中的标题/加粗文字为准，保持原始命名，不要自行归纳改名
- 汇总表格的"同左"仅指结论完全一致，有任何细节变化应写出来
- 所有临时文件（`/tmp/log_*.md`）读取完成后保留，不删除（用户可能还需要查看）
- 输出语言跟随日志文档的语言（通常为中文）
